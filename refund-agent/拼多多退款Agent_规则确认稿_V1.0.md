## 2. 自动退款条件

只有同时满足以下全部条件，Agent 才能执行自动退款：

| 规则 | 自动退款条件 | 不满足时 |
|---|---|---|
| 店铺与场景 | 店铺 ID 位于 3 家试点白名单，且退货退款场景已启用 | 非试点或未启用时跳过 |
| 售后类型与状态 | 拼多多退货退款，状态为待商家确认收货 | 非本期类型或已完结状态跳过；其他未完成状态转人工 |
| 本次退款金额 | 小于 500 元 | 大于或等于 500 元时高风险转人工 |
| 本次退货件数 | 1 至 4 件 | 5 件及以上高风险转人工；非法值转人工 |
| 物流方向 | 有效退货物流轨迹中出现“长沙”字段 | 未出现“长沙”时高风险转人工 |
| 物流更新时间 | 当前时间距最新物流节点小于 72 小时 | 大于或等于 72 小时时高风险转人工 |
| 平台处理倒计时 | 剩余处理时间大于或等于 72 小时 | 小于 72 小时时高风险转人工 |
| 必要信息 | 售后编号、订单号、店铺、金额、件数、物流单号、物流轨迹、最新物流时间及倒计时均可可靠读取 | 信息缺失或无法识别时中风险转人工 |
| 执行前复核 | 点击退款前重新读取上述信息，全部条件仍满足 | 条件变化时停止自动化并按最新状态跳过或转人工 |

### 2.1 边界说明

- 499.99 元可以继续判断，500 元必须转人工。
- 退货 4 件可以继续判断，5 件必须转人工。
- 最新物流节点距当前 72 小时整，必须转人工。
- 平台剩余处理时间 72 小时整，可以继续判断。
- “发往长沙”只要求有效物流轨迹中出现“长沙”字段，不要求已经到达长沙、签收或仓库确认到货。
- Agent 不自动点击“拒绝退款”；转人工也不等于拒绝退款。

## 3. 核心处理流程

1. 每 30 分钟读取 3 家试点店铺的待处理退货退款。
2. 按平台剩余处理时间从短到长读取任务。
3. 使用“店铺 ID + 售后编号”识别重复任务，已处理或正在处理的任务不重复执行。
4. 读取本次售后金额、退货件数、物流、最新物流时间和平台倒计时。
5. 执行自动退款规则判断；信息异常或任一条件不满足时转人工。
6. 满足全部条件时，在锁内重新读取并复核全部输入。
7. 留存退款前证据并记录执行意图后，点击确认退款。
8. 页面明确显示退款成功或售后完结时，记录自动退款成功。
9. 点击后结果不明确时，只能重新查询平台结果；仍无法确认则标记待验证并转人工，禁止再次点击退款。

## 4. 人工兜底

以下情况停止自动退款并进入人工处理：

- 退款金额大于或等于 500 元；
- 本次退货件数大于或等于 5 件；
- 物流轨迹未出现“长沙”；
- 最新物流超过或达到 72 小时未更新；
- 平台剩余处理时间小于 72 小时；
- 售后状态、金额、件数、物流或倒计时无法可靠读取；
- 拼多多页面异常、登录失效、验证码、按钮缺失或页面结构变化；
- 执行前状态发生变化且售后尚未完结；
- 点击退款后无法确认最终结果；
- 钉钉通知或其他关键依赖出现异常。

转人工后：

- 固定发送至“天猫抖音退款Agent通知群”，钉钉群号为 `189925002005`，标题为“拼多多退款工单转人工”；
- 同一售后单只生成一条人工工单和一条通知；
- Agent 不再自动退款，只跟踪人工处理是否完成；
- 结果未知时必须提示人工先核查拼多多最终状态，禁止直接再次退款。

## 5. 上线风险与控制

- 首批 3 家店铺直接执行真实退款，无影子模式；业务需知晓误退款、重复退款、漏处理、页面变化、账号风控和结果未知风险。
- 同一店铺、同一售后编号只能真正发起一次退款；重复扫描、并发执行、网络超时和进程重启不得造成重复退款。
- 自动退款前、执行结果和异常页面必须留存证据，并记录店铺、售后编号、规则版本、执行实例和时间。
- 出现误退款、重复退款、平台风控、页面规则失效或退款结果未知时，应立即暂停受影响店铺或场景。
- 自动化只能降低人工处理成本和超时风险，不能完全消除资金操作风险，异常情况必须由人工接管。

核心处理流程 自动化主线与异常分支

1每30分钟扫描→读取 3 家试点店铺并按剩余时间排序
2唯一键检查→按店铺 ID + 售后编号拦截重复任务
3字段读取→读取金额、件数、物流和平台倒计时
4规则判断→全部满足后锁内重读并再次校验
5执行退款→留存证据、记录执行意图、点击确认退款
6结果核验→明确成功则记录完成；不明确则转人工

自动退款成功

  • 页面明确显示“退款成功”或售后已完结。
  • 记录店铺、售后编号、金额、规则版本和操作时间。
  • 同一售后后续再次被扫描时直接跳过。
  • 自动成功只代表拼多多售后状态成功，不等于买家实际到账。

异常与人工分支

  • 字段缺失、页面异常或任一规则不满足时，不点击退款。
  • 点击后网络超时，只能重新查询拼多多最终状态。
  • 结果仍不明确时标记“待验证”，高风险转人工。
  • 转人工后 Agent 不再自动退款，只跟踪人工处理结果。
幂等说明

同一店铺、同一售后编号即使被重复扫描、并发获取，或在网络超时和进程重启后恢复，也只能真正发起一次退款。只要存在已准备、已提交或结果未知的执行记录，系统只能查询平台结果，禁止创建新的退款尝试。

看板接入

开发已有天猫看板，本期接入“天猫未收货退款”和“天猫退货退款”两个独立业务场景，分别统计、筛选、记录日志、转人工和启停。

未收货退款主流程 11家非海外店铺 · 订单状态为待收货

1每30分钟扫描→筛选未收货退款并按临近超时排序
2执行前读取→核验金额、件数、售后状态、物流、备注及同买家退款单量
3OMS低值品标记→区分低值品与非低值品路径
4规则完全匹配→执行退款、拒绝、协商或TMS快递工单
5字段/结果不明确→停止自动化并转人工

低值品

  • 以 OMS 现有低值品标记作为唯一判断依据，Agent不自行按金额推断。
  • 物流未到买家所在地：TMS创建“弃件”工单，提交成功后立即同意退款。
  • 物流已到买家所在地，包含派送、待取件或已签收：无需对接快递，直接同意退款。
  • 退款后添加低值品红旗备注；备注名称由业务在“低值品处理/低值品退款”中统一。

非低值品

  • 尚未在买家当地派件或签收，且发货物流仍在长沙：TMS创建物流拦截单并插旗备注，工单提交成功后立即同意退款。
  • 尚未在买家当地派件或签收，但发货物流已离开长沙：通过TMS发起物流拦截，物流出现明确的拦截或退回信息后再同意退款；尚无明确记录则继续复查。
  • 已到买家所在地并派件/待取件：TMS提交拒收，发送旺旺提醒并添加红旗备注。
  • 拒收后物流出现明确退回记录：同意退款；尚无退回记录则继续复查。
  • 原发货物流已签收：进入“协商退货退款”路径，不继续执行拦截/拒收步骤。

退货退款主流程 13家店铺 · 待收货/交易成功

1每30分钟扫描→筛选退货退款并按临近超时排序
2读取退货物流→核验金额、件数、单号、轨迹、目的城市及售后状态
3物流到达目标城市→无需等待签收，立即同意退款
4未填物流/临期→未填物流等待关闭；已填物流按48小时规则拒绝
5操作结果不明确→禁止重复退款，转人工核验

目标城市

  • 11家非海外店铺：退货物流到达长沙即可同意退款，无需等待签收。
  • zeamo海外旗舰店、dranlove海外旗舰店：物流到达义乌或金华即可同意退款。
  • 执行退款前再次读取最新物流；当前已明确签收地与退货地址不一致时转人工。

处理阶段

  • 客服SOP以买家已退回货物的退款申请为主；同意退货阶段原则上由人工处理。
  • 买家未填写退货物流：Agent不处理、不拒绝，等待平台超时自动关闭买家退货申请。
  • 买家已填写有效退货物流：读取退款申请内的实时倒计时，满足＜48小时拒绝条件时执行自动拒绝。
  • 物流单号、轨迹或平台状态无法可靠判断时，不使用默认值，直接转人工。

AI/自动化会按照当前规则进行判断和操作，但无法承诺上线后完全不出问题。页面变化、信息识别错误、物流更新延迟、人工同时操作或平台异常，都可能导致误退款、误拒绝、重复操作或漏处理。业务确认表示已清楚了解上述风险，并同意首批3家店铺在无影子模式下直接执行真实退款、拒绝退款及TMS快递工单；出现异常时由人工及时接管，并可暂停相关店铺或业务场景。

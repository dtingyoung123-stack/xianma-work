智能工单Agent数据看板重构方案

统一指标体系 · 统一交互框架 · 统一视觉语言 | Demo版本 v1.0

一、当前存在的问题

问题1：三个平台看板风格不统一

阿里系、拼多多、抖音三个页面各自一套KPI体系、图表布局和筛选交互，业务方需要切换页面才能对比，口径不一致。

问题2：缺少跨平台总览视角

没有一个页面能同时看到所有业务线的处理量、自动化率对比，领导和运营无法快速掌握全局。

问题3：时间筛选不联动

筛选日期后，KPI卡片仍显示今日数据，只有趋势图跟着变；且不支持月度数据查看。

问题4：下钻链路不顺畅

从场景分布无法直接点进订单明细，必须先点"自动化成功"才能看；抖音只能看总数，看不到具体业务类型数据。

问题5：退货退款未单独拆分

总工单量里退货退款是重要组成部分，但目前只有拼多多做了拆分展示，其他平台没有。

问题6：缺少时段分布视角

看不到一天中哪个时间段处理工单最多，无法判断人力/资源投入的高峰时段。

二、修改方向与建议

2.1 信息架构：两层结构

层级 改造前 改造后
第一层 三个独立页面，各自为政 跨平台总览页：7条业务线拉平对比
第二层 每个平台一套布局，风格各异 各业务线详情页：统一5模块模板
下钻链路 总览 → 平台 → 场景 → 订单（路径长） 总览 → 业务线 → 场景（可直接点） → 订单明细

2.2 统一KPI指标体系

统一5个核心指标

总工单量 → 其中退货退款量 → 自动化成功量 → 自动化率 → 未成功/异常量

全局时间筛选联动

顶部统一筛选器：今日 / 近7天 / 近30天 / 本月 / 自定义区间。选择后所有KPI、图表、表格全部联动更新。

2.3 详情页统一模板（5个模块）

模块 内容 对应需求
模块1：KPI条 5个核心指标横向排列 需求1、6：工单拆分 + 各平台自动化率
模块2：趋势图 工单量趋势折线图，随时间筛选联动 需求7：筛选日期后数据联动
模块3：时段分布 24小时处理量柱状图 需求2、8：哪个时段处理最多
模块4：场景分布 业务场景/类型分布，可点击下钻 需求3、5：从场景直接看订单
模块5：订单明细 从场景点进来的具体工单列表 需求3：订单详情查看

2.4 总览页布局（4个模块）

模块1：全局KPI条

总处理工单量 / 其中退货退款 / 自动化成功 / 整体自动化率

模块2：业务线对比表格

7条业务线横向对比：今日处理、退货退款、自动化成功、自动化率、累计处理

模块3：处理量趋势对比

多线折线图，各业务线每日处理量放在同一张图对比

模块4：自动化率排名

横向条形图，按自动化率从高到低排序

三、待业务确认事项

确认项1：总览页对比颗粒度

当前方案按业务线拉平对比（7条线：大健康/天猫国际/淘宝/淘工厂/小红书/拼多多/抖音）。是否需要额外增加"按大平台汇总"视图（阿里系汇总/拼多多/抖音）？

确认项2：订单明细表字段

当前demo展示：工单号、下单时间、平台/店铺、业务场景、处理状态、处理结果、处理耗时。是否需要增加或调整字段？（如：买家信息、客服/Agent、备注等）

确认项3：退货退款拆分口径

当前方案：总工单量下面单独拆出"退货退款"指标。各业务线是否都有这个拆分？还是只有部分平台需要？

确认项4：详情页模块灵活度

统一5模块框架下，是否允许各业务线在模块内容上做微调？（如：拼多多展示13个业务场景，抖音展示7种业务类型，位置相同但内容不同）

确认项5：导航架构选择 已确认

两种导航方案已在Demo中对比（左上角切换）：
• 方案一（平铺式）：左侧导航直接列出所有业务线，随时可切
• 方案二（层级式）：只有总览入口，点进详情后用面包屑返回
已确认：选择方案一（平铺式导航），2026-09-21 与客服开发确认。

确认项6：权限范围

当前Demo仅做页面级权限（控制不同角色能看到哪些页面/菜单），暂不做数据级权限（控制同页面内看到哪些数据）。
是否需要数据级权限？如：客服只能看自己负责的业务线、主管能看全部等。

## 1. 产品概述

### 1.1 一句话定位

AI 买家秀是一项面向电商商品种草与场景化内容生产的能力，用户选择商品品类和预设场景后，系统按场景规则自动生成一组真实可信的买家秀图片。

### 1.2 用户问题

电商设计人员需要围绕商品制作不同场景下的买家秀内容（如医疗康复、中老年居家、户外休闲等），现有人工流程存在以下问题：

- 每个场景需要重新构思人物、环境、光线、角度等要素，重复成本高；
- 场景规则分散在运营经验中，难以标准化复用；
- 批量生成过程中需要持续查看单图进度和质量；
- 生成结果需要逐张确认、返修和归档。

### 1.3 产品目标

1. 通过品类 + 场景预设，一键带出生成规则，降低场景构思成本；
2. 支持品类和场景库的增删改查及跨账号发布，沉淀组织级场景资产；
3. 在一个任务内统一管理分镜、结果图、评价文案和单图返修；
4. 将结果与历史记录连接，形成可继续编辑的生产闭环。

### 1.4 成功判断

本版不编造业务 KPI。功能交付成功以以下可观察结果判断：

- 用户能够选择品类和场景，系统自动带出场景规则；
- 用户能够新增、编辑、删除品类和场景，并将场景发布到公共库；
- 用户能够提交生成任务并观察逐张生成进度；
- 用户能够对单张结果进行点赞/待调整标记、下载和单图返修；
- 用户能够基于已确认结果批量生成评价文案；
- 任务结束后能够在历史记录中查看参数与结果。

## 2. 用户与使用场景

### 2.1 目标用户

- 电商设计人员；
- 需要批量制作商品买家秀内容的运营人员；
- 负责维护场景库规则的产品或运营管理员。

### 2.2 核心使用场景

#### 场景 A：从品类和场景生成买家秀

用户选择商品品类和预设场景，系统自动带出该品类的基础规则和该场景的差异规则，用户补充提示词并提交生成任务。

#### 场景 B：管理场景库

用户新增品类（填写品类名称、品类卖点和基础规则），在品类下新增场景（填写场景名称、描述和 6 个维度的差异规则），将成熟场景发布到公共库供全组织使用。

#### 场景 C：查看生成进度并处理结果

任务逐张完成后，用户在结果栏查看缩略图，对单图进行点赞、待调整标记、下载或进入单图返修。

#### 场景 D：生成评价文案

用户对已确认的结果图输入商品卖点，系统批量生成关联评价文案，逐条关联到具体结果图。

## 5. 核心用户流程

### 5.1 主流程

1. 用户进入 AI 买家秀页面；
2. 用户上传商品图片（当前原型占位）；
3. 用户选择产品品类，系统展示该品类下的场景卡片；
4. 用户在公共库或我的库中切换，选择目标场景；
5. 系统展示品类基础规则和场景差异规则的合成结果；
6. 用户填写综合提示词（可选），可使用 AI 润色；
7. 用户选择生成模型、清晰度、比例和张数；
8. 用户点击"提交任务"；
9. 系统创建任务并逐张模拟生成，任务卡片实时更新进度；
10. 用户对已完成图片进行点赞/待调整标记、下载或单图返修；
11. 全部完成后任务状态更新为"已完成"。

### 5.2 场景库管理流程

1. 用户点击配置区"场景"模块的"管理"按钮；
2. 弹窗展示公共场景库（只读）和我的场景库（可编辑）两个标签；
3. 在"我的场景库"标签下：
   - 点击"+ 新增品类"，填写品类名称、品类卖点和基础规则；
   - 选中品类后点击"+ 新增场景"，填写场景名称、描述和 6 维度差异规则；
   - 可编辑或删除已有品类和场景；
   - 点击"发布到公共"将场景复制到公共库（品类按名称去重）；
4. 关闭弹窗后，主页面实时更新场景列表。

### 5.3 评价生成流程

1. 用户在任务详情弹窗中切换到"评价文案"标签；
2. 系统自动带入当前品类的卖点（如有）到卖点输入框；
3. 用户选择生成数量（5/10/15/20 或自定义 1-20）；
4. 用户点击"批量生成评价"；
5. 系统基于已确认的结果图和卖点生成评价文案，逐条关联到对应结果图。

## 6.1 商品图片队列

### 6.1.1 输入规则

| 规则编号 | 规则 |
| --- | --- |
| R-IMG-01 | 最多添加 16 张商品图片 |

| R-IMG-03 | 支持 JPG、JPEG、PNG，单张不超过 20MB |
| R-IMG-04 | 支持从素材库选择和本地上传两种方式 |

**当前原型状态**：图片队列 UI 已展示（素材库选择 + 本地上传入库 + 已选图片展示），但点击后为占位行为，不触发真实文件选择和上传。本版 PRD 仅描述目标规则，实际接入待后续迭代。

## 6.2 品类与场景

### 6.2.1 品类

品类是场景的组织单位，包含：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 品类名称 | 文本 | 是 | 唯一标识，如"护腰带""护膝" |
| 品类卖点 | 文本 | 否 | 生成评价时的默认卖点文案，可手动修改 |
| 品类基础规则 | 文本 | 否 | 该品类所有场景生成时都遵守的硬约束 |

品类基础规则用于约束商品形态、佩戴位置等不可变要素。示例："以用户上传的商品图为基准，保持产品结构、颜色、材质与图案不变，禁止重新生成或臆造产品细节；护腰带需紧贴腰腹部。"

### 6.2.2 场景与规则维度

每个品类下包含多个场景，场景通过 6 个维度定义差异规则：

| 维度 | 说明 | 示例 |
|---|---|---|
| 人物 | 年龄/状态/表情/着装 | "60 岁左右中老年人，皮肤保留真实纹理，无磨皮痕迹" |
| 场景描述 | 具体地点/环境 | "医院康复科候诊区，米白墙面、窗边自然光" |
| 光线 | 明暗/光源 | "窗边自然光，柔和不刺眼" |
| 角度构图 | 机位/景别 | "半侧面、颈部以下构图，手机原相机抓拍感" |
| 动作姿态 | 在做什么/避免什么 | "坐在候诊椅上弯腰系鞋带，动作缓慢自然" |
| 真实感画风 | 整体基调/风格 | "生活化随手拍质感，非商业广告精修感" |

### 6.2.3 规则合成

生成时系统将品类基础规则与场景 6 维度规则合并为完整规则文本：

```
【品类基础】{category.baseRules}
【人物】{scene.dims.people}
【场景描述】{scene.dims.scene}
【光线】{scene.dims.light}
【角度构图】{scene.dims.angle}
【动作姿态】{scene.dims.action}
【真实感画风】{scene.dims.real}
```

仅填写了内容的维度才出现在最终规则中。

### 6.2.4 品类选择器

- 品类以可搜索下拉列表展示；
- 每项显示品类名称首字图标、名称、基础规则预览（去除公共前缀后的截断）和场景数量；
- 选中品类后自动带出该品类在当前库（公共/我的）下的第一个场景；
- 品类列表跨库并集（公共 + 我的），切库不改变已选品类；
- 品类在当前库没有场景时，场景区显示空状态提示。

### 6.2.5 场景展示

- 场景以 2 列卡片网格展示；
- 每张卡片显示场景名称、维度填写进度（如"3/6 维度"）和场景描述；
- 选中场景后自动合成并展示规则；
- 切换公共/我的库时，场景列表跟随当前库变化。

## 6.3 场景库管理

### 6.3.1 管理弹窗

- 弹窗固定高度，内容区独立滚动；
- 顶部两个标签：公共场景库（只读）、我的场景库（可编辑）；
- 左侧品类列表，右侧场景列表，两栏布局；
- 品类和场景的新增按钮固定在各自标题行右侧，不随列表滚动。

### 6.3.2 品类管理

| 操作 | 规则 |
| --- | --- |
| 新增品类 | 打开品类表单：品类名称（必填）、品类卖点（选填）、品类基础规则（选填） |
| 编辑品类 | 打开品类表单，回填已有内容 |
| 删除品类 | 二次确认后删除品类及其所有场景 |

仅"我的场景库"可编辑，公共库只读。

### 6.3.3 场景管理

| 操作 | 规则 |
| --- | --- |
| 新增场景 | 打开场景表单：场景名称（必填）、场景描述（选填）、6 维度差异规则（选填） |
| 编辑场景 | 打开场景表单，回填已有内容 |
| 查看场景 | 以只读模式打开场景表单 |
| 删除场景 | 直接从列表中移除 |
| 发布到公共 | 将场景复制到公共库；目标品类按名称去重（同名则复用已有品类），场景按名称去重（同名则覆盖描述和维度） |

发布时同时携带品类的卖点字段。公共库已有品类但缺少卖点时，以发布方的卖点补充。

### 6.3.4 数据持久化

- 当前原型为前端内存存储，刷新页面重置为内置默认数据；
- 目标：品类和场景数据应持久化到后台，按账号隔离；公共库为组织级共享；
- 本版 PRD 描述目标行为，持久化方案待技术确认。

## 6.4 综合提示词与 AI 润色

### 6.4.1 提示词输入

- 选填字段，自由文本输入；
- 用户填写的内容作为补充提示词，与场景规则合成后送入生成。

### 6.4.2 AI 润色

1. 用户点击标题行右侧"AI 润色"按钮；
2. 系统以浮层弹窗展示润色结果，弹窗从按钮所在模块上方展开；
3. 弹窗标题为"AI 润色"，右侧标注"已完成"状态；
4. 弹窗贴模块区域展开，不覆盖整个配置栏；
5. 用户可点击"取消"关闭弹窗并保留原文；
6. 用户点击"确认"后，润色结果替换输入框内容；
7. 未经用户确认，不得自动覆盖原文。

**当前原型状态**：润色逻辑为静态示例（在原文后追加固定文案），实际接入需对接 AI 润色能力。

## 6.5 生成模型与参数

### 6.5.1 模型

首版支持 5 个模型：

1. Nano Banana 2（默认）
2. Wan 2.7 Image Pro
3. Nano Banana Pro
4. Seedream 5.0
5. GPT Image 2

- 模型由用户手动选择；
- 每个模型展示图标、名称、能力描述和预计速度标签；
- 速度标签数值为占位示例，实际按平台模型配置动态展示；
- 模型选择器为向上展开的浮层下拉。

### 6.5.2 清晰度

- 可选 1K、2K（默认）、4K；
- 表示输出图片最长边像素档位。

### 6.5.3 比例

可选：智能比例、1:1、3:2、2:3、16:9、4:3（默认）、3:4、9:16。

### 6.5.4 张数

- 可选 1～9 张，默认 4 张；
- 以 9 格数字网格选择。

### 6.5.5 参数下拉

- 模型和参数的下拉面板均向上展开（`bottom: 100%`），避免超出视口；
- 点击面板外区域关闭。

## 6.6 提交生成

### 6.6.1 提交前校验

| 校验项 | 不满足时处理 |
| --- | --- |
| 已选择品类和场景 | 提示"请先选择产品品类和场景" |
| 生成中不可重复提交 | 按钮禁用，提示"正在生成中，请等待完成" |

### 6.6.2 提交行为

- 点击"提交任务"后直接提交，不增加确认弹窗；
- 提交后按钮文案切换为"生成中… N/M"并禁用；
- 任务卡片在右侧列表实时更新进度；
- 逐张模拟完成（原型每张间隔约 600ms），全部完成后按钮恢复为"提交任务"；
- 任务状态从"生成中"变为"已完成"。

### 6.6.3 清空

- 点击"清空"重置品类、场景选择和提示词；
- 如有正在生成的任务，先终止再清空。

**当前原型状态**：生成过程为前端定时器模拟，非真实后台任务。实际接入时需替换为任务队列回调驱动。

## 6.7 任务与结果

### 6.7.1 任务列表

- 每个任务以卡片展示：主商品缩略图、任务标题、任务 ID、模型参数、状态标签、进度条、分镜描述摘要、结果缩略图；
- 结果缩略图单行展示全部图片，不换行；
- 搜索框支持按时间/场景/请求 ID 过滤；
- 点击卡片选中任务，再次点击可打开详情弹窗。

### 6.7.2 任务状态

任务状态枚举与 AI 商品套图共用同一套：

| 状态 | 枚举标识 | 进入条件 | 页面表现 | 用户可执行操作 |
|---|---|---|---|---|
| 待配置 | `DRAFT` | 尚未提交任务 | 显示配置区 | 编辑配置、提交任务 |
| 提交中 | `SUBMITTING` | 用户提交任务，系统创建中 | 提交按钮禁用 | 等待 |
| 生成中 | `GENERATING` | 任务已创建且存在未完成图片 | 显示完成数/总数及逐图进度 | 等待完成，查看已完成图 |
| 已完成 | `SUCCESS` | 所有图片生成完成 | 显示全部结果缩略图 | 点赞、待调整、下载、编辑、查看评价 |
| 部分成功 | `PARTIAL_SUCCESS` | 至少一张成功且至少一张失败 | 同时展示成功与失败项 | 操作成功图、重试失败图 |
| 失败 | `FAILED` | 全部图片生成失败 | 展示失败原因及失败项 | 重试 |
| 已终止 | `CANCELLED` | 任务被终止 | 保留已完成图，未完成停止 | 操作已完成图 |

枚举值已确认，与 AI 商品套图一致。

### 6.7.5 单图返修

1. 用户点击结果图的"编辑"按钮；
2. 弹窗左侧展示当前图片和绘制工具（画笔/框选），右侧展示返修配置；
3. 系统自动展示本次返修继承的上下文（场景、规则、参数）；
4. 用户可选择快速返修方向（修正人物状态/修正佩戴位置/调整背景/提升真实感）或输入自定义补充要求；
5. 用户点击"生成候选"后涂抹选区并描述重绘内容；
6. 系统生成候选项，用户对比后选择替换或重新生成。

**当前原型状态**：返修候选生成为静态占位。弹窗内已标注开发注意——需调用图像模型重新生成，传入当前结果图 + 返修方向 + 补充要求。

## 6.8 评价文案生成

### 6.8.1 卖点输入

- 任务详情弹窗中提供"商品卖点"输入框；
- 首次打开评价标签时，自动带入当前品类的卖点（如有）；
- 品类卖点在品类表单中填写，发布场景时同步到公共库。

### 6.8.2 生成规则

**基本规则：**

- 生成数量可选：5、10、15、20 或自定义（1～20）；
- 仅基于标签为"认可"的结果图生成评价；
- 无已确认结果时提示"当前任务还没有已确认的结果图"；
- 重新生成会替换已有评价（二次确认）。

**图文绑定规则：**

- 每条评价必须至少引用 1 个从结果图中可观察到的视觉特征（如商品颜色、材质纹理、穿着/使用效果、场景氛围）；
- 禁止生成与图片内容无关的泛化文案；
- 系统先生成图片特征列表，再基于特征列表撰写评价正文。

**买家人设多样性：**

批量生成时系统随机分配买家人设风格，确保评价间有语气差异：

| 风格 | 字数范围 | 特点 | 示例 |
|---|---|---|---|
| 简洁实用型 | 30-60 字 | 直接说重点，不啰嗦 | "到货很快，包装完整，东西和图片一样，好评。" |
| 细节控/理性型 | 100-200 字 | 强调面料、做工、包装细节，逻辑清晰 | |
| 生活化/接地气 | 60-120 字 | 口语化表达，模拟真实购买场景 | "给老妈买的，收到就试了一下，颜色挺正的。" |
| 种草风格 | 80-150 字 | 含 Emoji，语气活泼、有感染力 | "哇这个质感真的绝了✨ 实物颜色超温柔！" |

**文本安全规则：**

- 生成文案不得包含：硬广推销词（如"赶紧购买""倾情推荐"）、非本商品品牌名、联系方式或导流信息（如"加微信""私信""其他平台更便宜"）；
- 不得使用绝对化用语（如"全网第一""百分百有效"）；
- 平台安全词库自动过滤，命中后标记并提示用户手动编辑或重新生成。

### 6.8.3 评价结构

每条评价包含：

| 字段 | 说明 |
| --- | --- |
| 关联结果图 | 对应的结果图 ID 和版本 |
| 评价正文 | 基于卖点、场景规则和图片内容生成的评价文案 |

### 6.8.4 评价操作

| 操作 | 规则 |
| --- | --- |
| 复制全部 | 一键复制所有评价文案到剪贴板 |
| 导出 Excel | 导出当前任务全部评价为 Excel 文件（原型为占位 Toast） |

#### 导出 Excel 字段与规则

| 导出字段 | 说明 |
|---|---|
| 序号 | 从 1 开始递增 |
| 关联分镜编号 | 评价关联的结果图分镜编号（如 01） |
| 关联结果图标题 | 分镜名称 |
| 评价正文 | 评价文案内容 |
| 生成时间 | 评价生成的时间戳 |

导出规则：
- 导出范围为当前任务下的全部评价，不跨任务；
- 仅导出当前任务已生成的评价，未生成评价的任务导出空文件或提示"暂无评价"。

### 6.8.5 数据埋点

以下指标供运营监控和产品迭代参考，埋点方案不在本 PRD 内定义：

| 指标 | 计算口径 | 用途 |
|---|---|---|
| AI 评价生成点击率 | 用户点击"批量生成评价"次数 / 评价标签页曝光次数 | 衡量功能使用意愿 |
| AI 评价采纳率 | 用户采用 AI 生成内容并成功提交/导出的次数 / AI 生成成功次数 | 衡量生成质量 |
| 编辑修改率 | 用户对 AI 生成文本进行手动编辑的评价条数 / 总生成条数 | 衡量内容可用性 |
| 平均修改字数 | 用户手动编辑的评价累计修改字数 / 被编辑的评价条数 | 衡量修改幅度 |
| 生成失败率 | 因超时、风控拦截或模型异常导致的生成失败次数 / 总生成请求次数 | 监控服务稳定性 |
| 每条评价平均生成耗时 | 从点击生成到全部评价完成的耗时 / 生成次数 | 监控响应性能 |

**当前原型状态**：评价生成为静态模板拼接，非真实 AI 生成。实际接入需对接文案生成能力及埋点系统。

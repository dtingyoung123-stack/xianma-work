## 3. 业务对象与共用数据要求

### 3.1 对象边界

| 对象 | 业务含义 | 已确认边界 |
|---|---|---|
| 素材资产 | 文件及其管理信息 | 素材与提示词的个人、团队、公共视图引用同一资产，不因跨平台读取重复创建 |
| 提示词资产 | 正文及其管理信息 | 普通跨平台读取使用同一资产；明确复制为个人资产时可按既有规则产生独立副本并记录来源 |
| 技能资产 | 个人技能或企业发布快照 | 个人技能与企业快照仍为不同对象，不因统一存储而合并 |
| 正式内容版本 | 一次确定的正式内容 | 已发布内容更新形成新版本；旧任务沿用实际正文、文件或技能包版本 |
| 个人分组及关联 | 用户在某应用中的整理习惯 | 保存于数据源，按用户和所属应用隔离；不是资产分类、共享范围或权限 |
| 应用任务输入记录 | 当次执行实际使用的输入 | 保留在应用任务记录，不作为第二份资产库 |

### 3.2 底座需要承接的共用信息

本表描述业务数据要求，不指定数据库表、技术字段名或存储方式。不是每一项都由用户填写；个人与共享资产所需归属信息也不能机械要求完全相同。

| 中文业务信息 | 用途 | 已有约定或边界 | 仍需补齐 |
|---|---|---|---|
| 资产编号、资产类型 | 跨平台识别同一对象并获取相应内容 | 底座返回资产编号，三库对象关系保持明确 | 编号生成、旧编号映射由研发设计 |
| 创建人、个人归属、归属组织 | 确定资产主体和追溯来源 | 个人归属跟统一账号走；团队与公共范围保留既有边界 | 保留创建与归属语义；无人维护不自动转移，按第6.2节及原授权核查 |
| 来源平台、来源记录 | 追溯新增或复制来源 | 来源平台不默认隔离资产 | 原有来源类型映射、外部灵感副本关系 |
| 分类、用途、标签 | 业务检索与展示筛选 | 不代替真实权限；各库分类词表可不同 | 词表维护、空值、条件组合、标签编辑权限 |
| 可见范围、维护权限、发布结果 | 一致的访问与写入判断 | 能看不等于能改；审批过程仍在业务端 | 第6.2节已确认角色边界；具体组织及角色映射待研发核查 |
| 内容与确定版本 | 获取文本、文件或技能包 | 正式内容不直接覆盖；旧任务不自动换成最新内容 | 变更版本规则见第6.3节，现有历史能力待研发核查 |
| 必要审批来源与结果关联 | 追溯获准写入 | 不复制审批流程、待办或审批中状态 | 业务服务具体提交哪些结果和关联信息 |
| 必要操作记录 | 追溯读写与冲突处理 | 整体方案要求受控读写与操作记录 | 记录范围、查询权限和留存要求 |

页面展示的上传人、创建时间、当前状态、验证状态及使用次数仍由研发核查来源映射。尤其不能将审批中状态、验证状态、资产可用状态混成一个状态，也不能将各应用使用次数直接相加冒充已确认的统一统计口径。

### 3.3 枚举、词表与状态口径

本节定义业务取值及字典边界，不预设数据库编码。已列出的目标取值纳入实现；依赖现有系统的完整字典和状态转换须在第一阶段设计评审中提交，不得在实现时无依据自定。

| 字段 | 取值或字典来源 | 默认值、空值及映射规则 |
|---|---|---|
| 资产类型 | 素材、提示词、技能 | 必填、单值；不因来源平台变化而改变类型 |
| 素材媒体类型 | 图片、视频、音频 | 单文件单值；MIME、扩展名和实际内容识别映射由研发核查，不将全部文件格式写成三种业务类型 |
| 素材／提示词共享范围 | 个人、团队、公共 | 单值；页面“团体”映射为“团队”。新增可选范围按原授权；默认项及组织空值沿用原规则并核查，不能默认扩大为公共 |
| 技能归属范围 | 个人、企业 | 单值；内置技能首期沿用原发布体系，不塞入员工归属枚举 |
| 提示词用途分类 | 通用、商品主图、详情页、买家秀、场景图、海报、视频 | 单选，默认通用；ID引用现有词表 |
| 素材类目 | 通用、医疗器械类、大健康类、宠物类、护具类、美妆类、进口保健品类、个护类、地毯类 | 单选，默认通用；ID引用现有词表 |
| 技能分类 | 引用管理后台技能分类词表 | 单选必填，无预设默认项。旧需求基线为办公协同、开发工具、投资理财、效率工具、内容创作、信息资讯、教育学习、数据分析、网站部署、生活服务、商业运营、知识与学习；研发核对当前完整词表和ID，不将旧基线直接覆盖生产词表 |
| 来源类型 | 引用分库来源字典；技能至少区分创建、文件导入、公开仓库、应用发布 | 完整来源值及旧值映射需研发提供；ZIP／文件夹／单Markdown是导入方式，不与共享范围或资产类型混用 |
| 技能输入类型、输出格式 | 引用现有包规范及应用支持的能力字典 | 多值；当前未取得完整可靠取值，研发核查完整值、未知扩展值保留和缺失值语义；空值不自动判为无限兼容 |
| 需要参考图 | 是、否 | 未勾选为否；是则执行时至少提供1张实际输入图，不用效果图代替 |
| 审批状态 | 保留各应用审批状态字典 | 业务端维护。技能旧基线为未提交、审批中、已撤回、已驳回、待发布、已发布、已下架，当前映射及新增值须核查；不作为统一资产可用状态直接复用 |
| 资产可用／企业发布状态 | 分别表达当前能否使用及是否发布生效 | 业务判定以权限、有效性及当前获准版本为准；物理枚举与合法转换由研发提出映射并评审，不把审批通过等同已发布，不以个人删除代表企业失效 |
| 验证、安装、兼容状态 | 保留原应用分别维护的字典 | 不合并为全局状态；研发提供值、含义及来源，未核实不凭展示文案补齐 |
| 标签、组织、分组、版本号 | 不是固定枚举 | 标签按数量长度校验；组织来自身份系统，分组属于用户与应用；来源版本号为文本，不用固定版本文本代替内容版本ID |

研发交接字典须逐项列出：业务值、技术编码、含义、单选／多选、默认值、空值、旧值映射、未知值处理、维护权限；状态另附合法转换、触发角色和生效条件。既有异常值进入兼容清单，不自动转公共、强行归类或丢弃。

## 4. 三库专属字段与规则

### 4.1 素材库与提示词库字段限制

### 4.5 三库员工个人删除规则

本规则适用于素材、提示词和技能，是已确认建设规则，不代表现有系统已实现。

- 员工个人删除仅移除个人侧记录或可见关系，不向员工提供完整物理删除入口；未共享资料也不得由员工操作直接触发完整物理清除。
- 已共享或已发布到企业的资料继续保留，个人删除不改变企业共享关系、企业可用状态或企业访问权限。
- 素材和提示词保持原有同一资产共享模型，只移除个人侧关系，不删除企业仍引用的资产；技能保留独立企业对象及其确定内容。
- 不得因个人删除连带清除企业引用的正文、文件、技能包及内容版本。
- 底层物理清理由系统按留存规则处理，不向员工提供直接入口。首期不建设自动物理清理；清理条件、留存期限需制度依据，执行中行为见第6.4节；企业失效后的历史查看及禁止重跑见第4.4.2节；本条不扩大管理员企业删除权限。

交付验收：三库分别验证员工删除后个人侧不再展示、企业侧仍可按原权限访问且内容完整；验证个人删除接口不会执行完整物理清除。企业删除、下架和撤权另按相应规则验收，不能混为个人删除。

## 5. 我的分组与存量字段处理

### 5.1 已确认的分组规则

统一数据源保存分组及资产关联，记录分组所属用户和所属应用。首期不强制跨平台共用分组；其他应用可以忽略分组，继续按资产权限、分类和标签读取同一资产，按需接入分组查询能力。

- 分组属于用户的个人整理关系，不改变资产归属、共享范围或维护权限；其他用户不自动继承该分组。
- 修改或删除分组只改变个人整理关系，不删除资产，不影响已有任务引用。
- 分组不是各应用的必填字段，也不作为统一分类或权限判断依据。

| 中文业务信息 | 用途 | 状态 |

### 5.2 历史超限内容

迁移时保留已有超限内容，不截断或丢弃。历史超限资产允许只改其他字段，修改超限字段时该字段适用新限制（见第6.1节）；研发提供名称、说明、正文、标签的实际长度分布及受影响记录数量，供产品复核。若需调整已确认上限，须记录新的确认结果。

必填项、标签等新校验也不能自动当成历史数据删除依据。缺失归属、无效分类、文件不可读等迁移异常按第一阶段确认的业务处理规则执行，不伪造缺失的历史信息。

### 6.4 失效、留存与迁移边界

- 员工个人删除按第4.5节，企业资料继续保留，不执行完整物理删除。
- 企业下架、删除或撤权后，禁止不获准的新调用和重跑；旧任务已保存内容和结果按任务权限查看，不因此重新授予原资产使用权。
- 执行中发生企业下架、删除或撤权时，停止后续受控读取、新生成及外部操作，保留已完成结果；对已启动的调用或操作尽力取消。无法中断的调用及无法撤销的外部动作须明确反馈，由研发核查覆盖，不承诺全部即时停止。
- 首期不建设自动物理清理；具体清理条件、留存期限及制度依据另行确定。管理员企业删除不等于立即清除被历史引用的底层资源。
- 迁移保留内容、归属、权限、旧编号及版本引用；不按名称自动合并。技能相同内容导入去重按第4.4节，不能将请求重试去重直接等同于所有资产内容去重。
- 切换发现丢失、越权或关键引用损坏，该批不通过；批次、窗口与回退设计由研发提出，再联合评审。

| 内容修改或发布 | 目标资产、基于版本、新内容、保存／发布意图、获准授权及请求标识 | 新修订ID、当前生效版本及“修订已保存／发布已生效”；冲突不覆盖，返回可访问当前修订信息 |
| 列表查询 | 身份、范围、应用筛选、排序分页 | 获准列表及分页；合法无结果为空，失败不是空列表 |
| 按确定引用读取 | 资产ID、指定或当前获准版本、身份及查看／使用用途 | 素材确定文件引用、提示词完整正文、技能完整包及必要声明；均返回确定版本。无权、失效、版本缺失、服务异常返回不同业务原因，不换最新内容 |
| 发布结果写入 | 获准业务服务、确定修订、业务记录引用及请求标识 | 发布已生效或明确未生效；超时结果待确认，按原请求标识核查／重试，不重复发布 |
| 新任务输入记录 | 实际输入、确定版本、执行配置及来源 | 任务ID、执行记录ID及保存确认；失败或结果未知时不执行 |
| 旧任务重跑 | 旧任务ID、可信身份、重跑请求标识 | 原输入可还原且有权执行时新建本次执行记录；返回旧任务ID、本次执行记录ID、状态及结果引用，不覆盖原输入及执行结果 |
| 个人删除 | 本人身份、目标个人记录 | 个人侧移除结果，企业关联和底层内容保留；不提供物理删除执行结果 |

- 超时或连接中断可能发生在写入完成之后，不能一律等同“未保存”。显示结果待确认，使用同一请求标识核查或安全重试；不可另发全新请求导致重复资产、版本或发布。
- 请求重试去重与内容重复规则是两件事；核查结果只返回有权读取的信息。
- 任务实际输入与本次执行记录必须确认保存后才执行。执行后结果记录失败时，明确报告执行与记录的真实状态，不因记录失败自动再执行外部动作。
- 修订保存成功不等于发布生效；待发布内容不自动替换当前生效版本。
- 历史任务无权限、记录不存在、原输入无法还原与服务异常分别表达；不把当前资产内容补成历史输入。
- 技术请求结构、核查接口、错误码及分页结构由研发设计，不在总方案预设。

## 7. 第一阶段交付的验收依据

### 7.1 底座验收要求

以下从原整体方案第 12.3 节迁入，作为第一阶段需要交付的验证要求，在第二阶段执行；应用任务记录与重跑完整链路在第三阶段验证。

| 产品跟进项 | 核心检查 | 验收证据 |
|---|---|---|
| 三库范围完整 | 素材、提示词、技能都支持本期约定的个人与共享资产能力，不能只用提示词通过代表全库通过 | 三库分别执行的结果记录 |
| 跨平台同一资产 | 同一用户从两个应用身份查询，获得同一资产编号、内容和归属；修改写回同一处 | 两个应用请求上下文的读写记录 |
| 权限与筛选分离 | 列表先满足访问权限再按业务条件筛选；已有引用不套用列表过滤；改查询条件不能读到他人私有资产 | 正向、排除筛选及越权反例 |
| 新增和修改结果可理解 | 保存成功才返回成功；重复请求不重复建资产；旧修订覆盖新内容时明确返回冲突 | 成功、失败、重试和并发修改记录 |
| 版本与历史读取 | 正式内容更新不覆盖原版本；底座支持按确定版本获取文件、正文或技能包 | 新旧版本对比及固定版本读取结果 |
| 业务结果写入 | 有权业务服务能够保存审批后的发布结果；无权写入被拒绝；失败不能伪报已发布 | 发布结果写入及冲突记录 |
| 删除与失效 | 按第一阶段确定的规则处理删除、下架、撤权及已有引用；不把“不展示”当成“已删除” | 相应条件下的响应和资产状态 |
| 接口可交接 | 接口说明使用清楚的业务解释，包含筛选示例、操作结果、错误原因和两端需配合事项 | 接口说明与联调清单 |

### 7.2 共性规则的最小验证集

| 样例 | 需要验证的结果 |
|---|---|
| 本人个人资产、他人个人资产 | 本人按授权读取，他人私有资产不能越权访问 |
| 团队、公共／企业资产 | 相应可见范围正确，能使用不自动获得编辑权 |
| 带有被某应用排除标签的资产 | 列表不展示，但已有引用在实际权限允许时仍可读取 |
| 已发布内容的旧版本与新版本 | 新查询按规则获得当前版本，指定旧版本仍定位原内容 |
| 两个应用同时编辑同一资产 | 无提示覆盖被阻止，冲突原因可交回业务端处理 |
| 请求超时后重试 | 不重复新增资产或重复产生同一发布结果 |
| 业务端审批通过但底座写入失败 | 结果可追溯，业务端能够识别未生效，不错误显示已发布 |

各库使用等价样例验证共性规则，并保留文件读取、提示词正文、技能包完整性等专属检查。样例覆盖个人与共享范围，不要求构造无意义的维度组合；测试数据使用受控样本。

### 7.3 字段规则的边界样例

| 样例 | 预期行为 | 前置条件 |
|---|---|---|
| 新增素材名称或提示词名称为 100／101 字符 | 100 满足长度限制；101 不满足长度限制 | 按后续统一计数口径；其他保存条件均满足 |
| 用途说明为 500／501 字符 | 500 满足长度限制；501 不满足长度限制 | 不据此推断是否必填 |
| 正文为 5,000／5,001／10,000／10,001 字符 | 5,000 不触发长度提醒；5,001 与 10,000 提醒但不因长度阻止保存；10,001 不满足新内容上限 | 按研发评审的一致计数口径；历史超限编辑见第6.1节 |
| 标签为 10／11 个，单标签为 20／21 字符 | 分别检查数量与单项长度上限 | 拆分、去首尾空格、移除空项、去重后校验；大小写及计数按研发一致方案 |
| 标签带首尾空格或出现重复项 | 去除首尾空格与重复项 | 大小写判重与计数由研发提出一致方案，影响业务时联合评审 |
| 设计平台存在个人分组，Studio 未接入分组功能 | Studio 仍可按权限与自身筛选规则读取资产 | Studio 不把设计平台分组作为必填条件 |
| 修改或删除个人分组 | 资产本身、共享权限和已有任务引用保持有效 | 只修改分组及关联，不额外执行资产操作 |
| 迁移历史超限正文 | 原文完整保留，不截断或丢弃 | 允许改其他字段，修改超限字段时适用新规则 |

以上用例用于后续验收。

### 7.4 补齐规则的验收样例（后续执行）

| 场景 | 预期结果 |
|---|---|
| 名称纯空白、同名资产 | 空白不允许；同名可保存且ID不同 |
| 素材说明500／501字符 | 500允许，501拒绝；不覆盖其他批次素材 |
| 提示词效果图3／4张、格式／大小不符 | 3张允许；超数量或约定格式、大小拒绝，提示原因 |
| 要求参考图但任务无图 | 阻止执行并提示补图；展示效果图不自动计入输入 |
| 企业技能无标签 | 仍可按原获准流程发布 |
| 分组同用户同应用重名／跨应用同名 | 前者拒绝，后者允许；同资产可关联多个分组 |
| 多维筛选、同维多选、空结果、服务异常 | 交集／并集正确；合法空列表与失败明确区分 |
| 他人个人资产、停用账号、无权管理员 | 拒绝越权读写；不影响企业共享资料留存 |
| 历史超限正文只改标签／修改正文 | 只改标签允许；修改正文须满足新上限；未改原文完整保留 |
| 三库个人删除 | 个人侧关系移除，企业仍按原权限读取，文件正文包内容完整，无物理清除 |
| 内容更新与管理信息修改 | 内容变化新版本；分类标签不重建包，旧任务原输入不变 |
| 下架／撤权发生在执行中 | 停止后续受控读取和外部操作，保留已完成结果；不可中断能力明确报告 |
| 归属不明、文件损坏、关键引用缺失 | 列入异常清单，不自动删除或转公共；相关记录不通过该批切换 |

| 写入超时但实际已保存 | 展示待确认，原请求标识核查／重试返回同一结果，不重复资产或版本 |
| 修订保存与发布生效 | 两种结果及当前生效版本明确区分，未发布修订不替换当前内容 |
| 输入或执行记录保存失败 | 不启动执行／重跑；结果未知先核查，不盲目重复执行 |
| 历史记录不存在／不可还原／服务异常 | 分别提示，不用最新内容替代历史输入 |
| 重跑成功及结果记录失败 | 新执行记录关联旧任务，原记录不覆盖；记录失败不自动重做外部动作 |

以上仅为验收要求，未执行生产测试。

产品范围和关键业务规则可执行，开发完成必要事实核查，形成可评审的数据模型、接口范围、两端改造和迁移方案；产品与研发对影响范围和验收口径无关键分歧。负责人和排期按真实工作量安排。

产品业务规则可交研发评审；仍需实际入口、权限映射、容量、包兼容、历史可还原性及留存制度依据。第一阶段只有联合设计评审及必要核查完成后才可关闭，不宣称已完成开发或上线。

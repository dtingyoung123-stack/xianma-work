# 天猫物流监控 Agent 业务规则确认版 V1.0

> 状态：业务已确认  
> 版本：V1.0  
> 整理日期：2026-11-07  
> 适用项目：天猫物流监控 Agent  
> 资料来源：业务提供的《天猫物流监控操作流程》及 2026-11-07 补充确认

## 一、确认结论

衡风 API 负责筛选需要处理的物流异常数据，并向 Agent 返回订单号、对应物流单号及已判定的业务场景。Agent 不重新计算 24 小时或 48 小时，不再次筛选异常类型，直接根据 API 返回的场景执行对应操作。

本期覆盖四类物流监控场景，所有正常流程均由 Agent 自动处理。正常催揽收发送到钉钉群“24H支付揽收率监控群”，并 @易嘉豪、陈娇群、崔志文、何紫辉、彭心雨、曾昶、张欣、刘敏；OMS 显示缺货或任一操作失败时，Agent 在钉钉群“天猫物流监控”内通知并 @刘敏。

## 二、统一业务规则

1. 数据来源：衡风 API。
2. API 只返回已经筛选、需要 Agent 处理的数据。
3. API 返回订单号、订单号对应的物流单号及业务场景。
4. 24 小时、48 小时及派件异常等状态以 API 返回结果为准，Agent 不自行重新计算。
5. 正常催揽收发送到“24H支付揽收率监控群”，并 @易嘉豪、陈娇群、崔志文、何紫辉、彭心雨、曾昶、张欣、刘敏进行催促。
6. OMS 显示缺货时，在“天猫物流监控”群内 @刘敏处理。
7. 无待处理数据时正常结束；API 调用失败、必填字段缺失、页面操作失败、OMS 补发失败、物流工单创建失败、备注或插红旗失败等操作异常，均按失败规则处理。
8. 在 OMS 填写的卖家备注和红旗备注必须同步回传到天猫平台。
9. Agent 以“订单号 + 物流单号 + 场景”作为任务唯一标识；成功任务不重复执行、不重复发群。
10. 任一步骤失败后自动重试 1 次；重试仍失败时，发送到“天猫物流监控”群并 @刘敏。
11. 人工处理后，以衡风 API 后续不再返回该异常作为任务结束依据。

## 三、场景处理规则

### 场景一 物流等待揽收

**触发条件**  
衡风 API 返回“物流等待揽收”场景及对应订单号、物流单号。

**Agent 操作**

1. 根据订单号读取对应物流单号。
2. 将物流单号发送到钉钉群“24H支付揽收率监控群”。
3. @易嘉豪、陈娇群、崔志文、何紫辉、彭心雨、曾昶、张欣、刘敏，执行“催促揽收”。
4. 订单产生揽收记录后，该异常自动消失。

### 场景二 包裹揽收超时超过 24 小时

**触发条件**  
衡风 API 返回“包裹揽收超时超过 24 小时”场景。该场景表示仓库尚未发出包裹。

**Agent 操作**

1. 复制对应订单号，在 OMS 查询订单状态。
2. OMS 显示缺货字段：在“天猫物流监控”群内 @刘敏处理缺货异常，本次自动流程停止。
3. 订单状态正常：在 OMS 输入订单号并点击“补发”。
4. 补发原因选择“快递责任补发”。
5. 在 OMS 填写卖家备注“超时未发出重新补发”，并同步回传到天猫平台。
6. 确定补发后，进入对应补发订单。
7. 依次选择“更多操作”“卖家备注”，选择红色备注旗并填写“超时未发出，已重新补发”。
8. 勾选“同步至平台”，选择“叠加”，确认保存并回传到天猫平台。

### 场景三 物流已发出后运输停滞

衡风 API 已完成时间状态筛选，Agent 直接按返回场景执行，不自行计算 48 小时。

#### 运输停滞 48 小时以内

1. 进入客服工单系统。
2. 打开“物流问题登记表”。
3. 创建物流工单。
4. 选择“催件”。
5. 客服备注填写“物流停滞，麻烦尽快更新物流”并提交。

#### 运输停滞超过 48 小时

1. 进入客服工单系统。
2. 打开“物流问题登记表”。
3. 创建物流工单并选择“丢件”。
4. 客服备注填写“物流48小时未更新物流，我司记丢件，重新补发”并提交。
5. 在 OMS 对该订单执行补发。
6. 补发原因选择“快递责任补发”。
7. 在 OMS 填写卖家备注“物流丢件”，并同步回传到天猫平台。
8. 确定补发后，进入对应补发订单。
9. 依次选择“更多操作”“卖家备注”，选择红色备注旗并填写“物流丢件已重新补发”。
10. 勾选“同步至平台”，选择“叠加”，确认保存并回传到天猫平台。

### 场景四 包裹到达买家当地后派件异常

**触发条件**  
衡风 API 返回“派件异常”场景。

**Agent 操作**

1. 进入客服工单系统。
2. 打开“物流问题登记表”。
3. 创建物流工单。
4. 选择“催件”。
5. 客服备注填写“派件超时，麻烦尽快处理”。
6. 提交工单。

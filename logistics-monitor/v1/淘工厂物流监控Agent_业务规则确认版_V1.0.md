# 淘工厂物流监控 Agent 业务规则确认版 V1.0

日期：2026-11-07；更新：2026-11-12。状态：业务规则及钉钉对接群信息已确认，投递配置待联调；未开发、未部署、未上线。

## 1. 范围与依据

物流异常自动处理仅覆盖淘工厂后台四个场景：已揽收待物流更新—即将超时、已揽收待物流更新—已超时、运输中待派送—即将超时、运输中待派送—已超时。不处理支付18—24小时未揽收。另新增独立通知：淘工厂所有原因的补发订单，补发单配货仓库名称含“店管家”且仍需安排发货时，推送客服对接微信群安排代发仓发货；不受四场景或补发创建人限制，不扩展其他原因的自动建补发单及回填。

物流异常直接按后台状态筛选，不自行计算48小时或超时阈值。已退款、已签收、物流恢复更新的订单由页面自动移出异常列表，不再新增物流处理动作；不因此删除已有待回填任务或停止独立店管家发货交接扫描。

本次为自动处理Agent的新业务范围；旧通知看板规则不作为本次自动处理边界。新增处理数据接入既有淘工厂子报表及跨平台汇总，具体增量只写入淘工厂PRD，不修改旧报表PRD或其他业务线规则。

## 2. 每日流程

每日执行一次，采用本轮认可的上午9:30建议时点。每日回传昨天补发订单的新运单到淘工厂后台，并处理当天四个场景。未发货补发单保留待回填，后续每日继续检查（本轮建议获用户“好的”承接，作为防遗漏规则纳入本版复核）。

补发回填：OMS查看补发订单发货信息，取得快递公司及新运单号；淘工厂后台找到对应原订单，通过“修改发货信息”填写并保存。新运单回填后台成功后，补发任务完成。

同一每日批次还需从OMS独立检查淘工厂所有原因的待发货补发单，读取补发单配货信息；含“店管家”的补发单按纯文本推送。本Agent当天新建的补发单也检查，配货信息尚未生成则保留后续每日复查。同一补发单同一通知用途成功后不重复推送，不要求先有新运单。

## 3. 仓库分流

OMS查询原订单发货仓库。支持TMS的仓库沿用业务输入清单：筑越仓、代发聚水潭-亿哈、代发聚水潭-铭如、代发聚水潭-简卓、代发聚水潭-品动工贸、代发聚水潭-众邦、代发聚水潭-捷佑、代发聚水潭-代发仓瞳琪、代发聚水潭-迅发、代发聚水潭-祺迦工贸。

清单以外仓库推送人工客服；不支持TMS的代发仓通过钉钉对接群转人工微信处理。店管家代发仓补发对接携带订单号与配货单号。

## 4. 即将超时：催件

两个即将超时场景采用同一流程。支持TMS的仓库进入“物流问题登记表（客服）”，输入OMS订单号并查询，物流问题选择“催件”，客服备注填写“催件”并提交。提交成功即完成，不跟踪快递回复。

已催件订单无需重复操作。不支持TMS的仓库推送钉钉对接群，由人工对接微信催件。

### 4.1 TMS新建工单公共附件规则（2026-11-12确认）

所有TMS新建物流工单（催件、拦截退回、弃件）统一上传当前淘工厂原订单详情截图至“客服附件”，单文件≤10MB。路径：淘工厂后台→订单管理→近3个月订单→全部→输入原订单编号→点击“查询”→对应订单“订单详情”→截图。截图必须清晰包含原订单号、原物流单号及完整收货信息（收货人、手机号、收货地址），不脱敏；不额外要求商品明细完整入图。页面隐藏信息时，使用账号已授权的查看完整信息能力展开后截图；具体控件、权限和展示效果待技术联调，不假定单一眼睛按钮能展开全部字段。无法查看完整信息、未查到订单、物流单号为空或“－”、截图截断／错单／文件超限时，不提交该新建工单；修正后从取图断点恢复。上传后确认成功，提交后重新查询工单确认附件已保存；结果不明先查TMS，已有成功工单直接复用，不重复创建。已有工单修改复用原记录及附件，不新增每次修改重新上传要求。

操作示例：[查询入口](./淘工厂物流监控Agent_PRD_截图/补充6_附件原单查询入口.png)；[截图区域](./淘工厂物流监控Agent_PRD_截图/补充7_附件订单详情截图区域.png)；[必含信息位置](./淘工厂物流监控Agent_PRD_截图/补充8_附件必含信息示例.png)。示例订单为待付款、物流号“－”且收货信息隐藏，仅说明入口与截取位置，不是可提交的合格实单附件，也不扩展四场景范围。

## 5. 已超时：普通商品拦截补发

支持TMS、无原催件记录：新建物流工单，问题选择“拦截退回”，客服备注填写“拦截退回”，附件上传淘工厂后台原订单详情截图后提交。附件按下述统一规则获取和核验。

已有催件记录且从即将超时流转到已超时：修改原物流对接记录，问题由“催件”改为“拦截退回”；客服备注追加“日期＋拦截退回”，例如“11.7 拦截退回”，保留原备注，不覆盖历史记录。完成修改后安排补发。

TMS拦截提交成功即可补发，无需等待拦截结果。不支持TMS的代发仓推送钉钉群成功后即可补发，由人工微信拦截，无需等待拦截结果。

## 6. 已超时：低值品

使用OMS“低值品”标记识别，不自行增加金额标准。支持TMS的仓库对接物流“弃件”，同步补发。已有催件记录时，改原记录为“弃件”，追加“日期＋弃件”备注，保留原备注，再补发。

不支持TMS的代发仓推送钉钉群，由人工微信拦截；推送成功后即可补发，不等待拦截结果。本版仅使用本轮明确确认的低值品规则，不引入其他拼多多规则。

## 7. 物流异常自动补发要求

本Agent因四类物流异常创建的补发单：OMS整单补发，不拆单品；补发仓库采用系统默认仓库。业务类型“快递责任补发”，买家备注“物流监控补发”。确认商品明细后按原流程下一步确认保存。补发后缺货推送「【物流监控】淘工厂」并@楚乔。其他原因补发单只适用新增店管家发货交接规则，不强制改为上述业务类型或备注。

补发单创建成功不等于任务完成；等待发货并回填新运单成功才完成。

## 8. 通知与待落实事项

群用途：不支持TMS仓库的人工对接、代发仓微信拦截转交、补发缺货异常，以及淘工厂所有原因补发单的店管家发货交接。2026-11-09用户补充确认：群名「【物流监控】淘工厂」，钉钉群号「186730016529」，群消息 @楚乔。群业务信息已齐备；技术仍需将群号映射至发送工具所需的群会话标识、将楚乔映射至对应人员标识，并验证发送权限与投递回执。群号不直接冒充接口会话标识，尚未验证实际投递成功。

通知采用精简纯文本。催件／拦截带原订单号、原发货仓、原配货单号、原发货单号（即运单号，OMS发货信息）；缺货带原订单号、补发单号及补发仓；店管家发货交接带原订单号、补发单号、补发单配货仓库、补发单配货单号，不要求尚未生成的新发货单号。配货单号在OMS“配货信息”中获取，不能用OMS订单号或运单号代替；字段与模板详见PRD的R-08及R-10。通用失败重试次数留技术评估，不沿用天猫规则。

## 9. 报表影响确认

2026-11-09确认：转人工按Agent职责完成计入，不要求跟踪客服微信或快递回复。纯催件交接、店管家发货交接以群投递成功为转人工完成；物流补发仍承担后续回填职责，群交接后继续补发并回填，回填核验成功后归转人工完成。未转人工的催件提交及物流补发回填归AI独立完成。

子报表按任务创建日集合查询最新状态，汇总完成量按职责完成日；AI覆盖率继续展示，公式为进入自动化量÷工单总量（参考）。参考量沿用既有人工实际处理量，范围不完全一致时提示参考差异，不直接隐藏覆盖率，不叠加AI完成量；真实分母为0、缺失或维度不支持等不可计算时显示“—”。详细任务粒度、通知防重、历史保留、字段及验收见淘工厂PRD第12节。旧通知不追溯转换为完成，其他业务线不变。

场景筛选沿用线上6项：24小时未揽收、揽收后即将超时、派送即将超时、揽收超时补发、揽收后超时补发、派送超时补发；末尾新增“店管家补发待发货交接”，共7项＋“全部场景”。其中“24小时未揽收”“揽收超时补发”仅保留原通知及历史查询，其余4个原场景增加处理统计；店管家为新增独立交接场景。不是将旧6项替换为5项。

2026-11-10补充操作：OMS订单管理按原单号及店铺定位并选中原单，打开订单行操作菜单→“补发”→基本信息（快递责任补发、买家备注“物流监控补发”、默认仓）→商品明细整单核对→支付信息及最终确认→重新查询补发单保存关联。基本信息的“下一步”不代表建单成功；详细逐步操作与异常恢复见PRD第6节。商品明细、支付信息和最终保存控件的完整页面尚待技术联调核验。

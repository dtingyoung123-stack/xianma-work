# V2.1.0 定时任务 MVP 原型说明

> 状态：产品方案已确认，静态原型已完成，待用户评审  
> 产品版本：V2.1.0  
> 说明：本文件记录原型交互，不代表生产能力已实现或上线。

## 1. 目标

把原“已安排”展示页补成可创建、可执行、可追溯的定时任务 MVP。员工既能在定时任务页直接新增，也能在普通对话中用自然语言或 `/定时任务` 创建；两种入口最终使用同一份任务确认与运行记录。

## 2. MVP 范围

- 支持单次、每天、每周。
- 支持新增、编辑、启停、立即运行、删除确认、查看记录和人工补跑。
- 支持在普通对话中识别任务内容、周期和时间；信息不足时追问。
- 创建后冻结任务指令、周期和工作区，后续普通消息不隐式修改。
- 每次执行形成独立记录，结果摘要回写创建任务的对话，并可进入现有任务结果页。
- 定时任务只在客户端在线或后台常驻时执行；客户端关闭期间到期的任务记为“已错过”，重新打开后允许人工补跑。

## 3. 双入口流程

```text
定时任务页 → 新增定时任务 → 填写任务与时间 → 确认创建 → 进入任务列表

普通对话 → 自然语言或 /定时任务 → 信息不足时追问 → 任务草稿卡 → 确认创建 → 回写当前对话并进入任务列表
```

定时任务草稿至少展示任务名称、任务指令、周期、首次运行时间、工作区和创建后状态。只有时间没有任务内容时不得创建。

## 4. 任务与运行状态

- 任务状态：运行中、已暂停、已错过、已完成。
- 运行状态：待确认、执行中、执行成功、执行失败。
- `立即运行` 与 `补跑`不改变原定计划。
- 单次任务成功后进入已完成；周期任务继续保留下一次计划。
- 失败后本期只提供人工补跑，不做自动重试。

## 5. 权限规则

- 每个任务最多绑定一个授权工作区；越界文件要求重新选择。
- 高风险动作或缺少授权时暂停执行并进入待确认。
- 文件正文需要发送模型时继续使用单次内容授权，不因定时任务创建而永久授权。
- 未授权时不读取、不上传、不生成结果。

## 6. 本期不做

- 每月、自定义 Cron 或事件触发。
- 客户端关闭后的云端无人值守执行。
- 技能组合、复杂工作流、多任务依赖和自动重试。
- 企业共享定时任务模板和多设备同步。

## 7. 原型演示口令

- `测试定时任务`：生成“每周一 09:00 生成上周周报”的待确认草稿。
- `每天18点整理今天的工作记录`：自然语言创建每天任务草稿。
- `/定时任务 每周一9点生成上周周报`：显式命令创建每周任务草稿。
- `每天9点`：触发缺少任务内容的追问，不创建任务。

## 8. 验收

- 公共侧栏、搜索页和页面标题统一显示“定时任务”。
- 列表页可新增单次、每天和每周任务，并能编辑、启停、立即运行、删除和查看记录。
- 对话中的自然语言、显式命令和页面入口生成同一结构的任务草稿。
- 未确认草稿不写入任务列表；只有时间没有任务内容时只追问。
- 已错过任务可补跑；补跑不改变原定计划。
- 1024px 与 1280px 下无文字遮挡、整页横向滚动或公共侧栏跳动。
- 所有系统图标来自 `<xianma-icon>`，控制台无缺失图标或脚本错误。

- 已验证新对话中的自然语言、`/定时任务`、建议项、信息不足追问、草稿确认和跨页面列表同步。
- 已验证现有任务对话内创建定时任务，以及“已错过”单次任务补跑后进入“已完成”并写入独立运行记录。

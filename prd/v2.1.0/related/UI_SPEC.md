# 先马·AI Studio V2.1.0 轻量 UI 规范

> 版本：V2.1.0  
> 更新时间：2026-09-01  
> 适用范围：本目录后续新增或调整的桌面端与嵌入式管理端原型

## 1. 设计原则

1. 任务优先：常用操作直接可见，信息密度适合重复使用。
2. 状态清晰：审批、发布和异常状态同时使用文字与颜色，不只依赖颜色。
3. 操作可控：撤回、下架等操作明确影响范围；破坏性操作必须二次确认。
4. 宿主一致：管理端继承聚合管理后台外壳，模块内只使用顶部导航。
5. 桌面优先：目标宽度为 1280px；最低验证宽度为 1024px，不设计移动端业务流程。

## 3. 布局

- 桌面应用：1280×820 基准窗口，左侧栏 260px，内容区最小左右留白 32px。
- 除登录页和独立受控浏览器窗口外，应用端页面统一复用 `assets/v210-app-sidebar.js` 公共侧栏组件；品牌区、一级导航、项目/普通对话列表和底部账号区不得在页面内另造结构或样式。需求提报和我的提报页面继续展示同一套项目/普通对话列表，不新增需求提报对话历史列表；需求草稿状态只在需求提报主工作区表达。
- 应用端公共外壳的唯一样式事实源是 `assets/ui-tokens.css`。正式页面必须在 `<head>` 静态加载该文件，并在首屏 HTML 中直接使用 `app-window`、`app-body`、`window-dot` 和 `xianma-app-sidebar`；标准内容区使用 `app-main`，有独立分栏契约的业务主区可使用模块类。不得等待页面末尾脚本加载后再补类名或侧栏宽度，否则会造成切页时窗口和内容区跳动。
- 公共外壳在宽度大于 900px 时使用 18px 画布留白、最大 1280×820 窗口和 260px 侧栏；宽度不超过 900px 时窗口铺满视口、侧栏调整为 220px。页面局部样式不得覆盖这些尺寸、定位和响应式规则。
- `v210-app-sidebar.js` 中的旧页面转换逻辑只作为历史页面兼容兜底；新增页面和本版本继续维护的正式页面不得依赖运行时转换完成首屏布局。
- 正式应用页面必须在 `<head>` 直接加载 `assets/v210-app-sidebar.js`，不得通过页面底部的 `v210-account-menu.js` 再动态追加公共侧栏脚本；`v210-account-menu.js` 仅保留为历史兼容入口，不作为 V2.1.0 正式页面依赖。
- 管理后台：沿用宿主左侧栏与顶部账户栏；AI Studio 使用深色模块标题条和顶部横向导航。
- 页面分区不使用浮动卡片包装；卡片只用于单个技能、状态摘要和弹窗。
- 列表在 1280px 使用 3 列，1024px 使用 2 列；表格保持水平滚动，不压缩操作区。

## 4. 控件

- 主按钮：山茶红实底，仅用于每个区域的首要动作。
- 次按钮：白底描边；危险按钮使用红色文字或红色实底。
- 应用导航：一级入口固定按“新对话、搜索、技能库、提示词库、定时任务、需求提报”排列；“需求提报”位于末尾并通过分隔线与日常任务入口区分。固定使用公共图标组件中的 `square-pen`、`search`、`zap`、`lightbulb`、`clock-3`、`clipboard-pen-line` 对应上述入口；选中态只改变背景、文字粗细和图标颜色，不替换图标。
- 账号下拉菜单：点击侧边栏底部“梦蝶”账号区域向上展开，固定按“系统设置、退出登录”排列；需求提报只保留左侧一级入口，不在账号菜单重复展示；“退出登录”进入登录页，点击菜单外或按 Esc 关闭。
- 页签：文字 + 底部 2px 指示线，不使用胶囊导航。
- 状态标签：圆角 4px，必须显示状态文字。
- 输入框：高度 40px，圆角 6px，聚焦时显示品牌色边框与浅色焦点环。
- 斜杠菜单：统一承载可调用的技能与工具；输入斜杠关键词时按技能/工具名称、别名和关键词做包含匹配，无结果显示空态；选择后在输入框内显示山茶红命令标签，由用户继续补充任务描述；命令标签支持移除和重新选择。浮层高度必须受输入区上方的工作台可用空间约束，超出时仅技能与工具列表独立纵向滚动，标题和“查看全部技能”保持可见，不得被窗口标题栏裁切。
- 技能库范围页签固定为“全部技能、我的技能、企业技能”。全部技能仅展示当前员工可调用的企业已发布技能和自己的个人技能，以来源标签区分，不展示状态筛选；个人状态只在“我的技能”中展示。
- 技能库分类使用横向一级标签栏，默认“全部”，按后台启用分类展示；超出容器横向滚动，并提供箭头提示查看更多。分类为单选筛选，不使用下拉框。
- 可检索选择器：输入区、下拉面板、选项行、选中标记和焦点态使用同一套公共样式。
- 分类选择：使用可检索的单选下拉；显示当前选中值和选中标记，不提供新增入口。
- 标签选择：使用可检索的多选下拉；已选项显示为可移除标签，没有匹配项时提供直接新增。
- 卡片：圆角不超过 8px；悬停只改变边框与轻微阴影，不移动布局。
- 表单弹窗：宽度 480-640px；包含标题、影响说明、取消和确认按钮。
- 内容浏览弹窗：宽度 800-960px；用于在线技能库等需要搜索和浏览列表的任务，列表区域独立滚动，标题与搜索区保持可见。
- 在线技能列表：每行展示图标、名称、简介、GitHub 仓库所有者、公开仓库来源、兼容状态和安装状态；不展示无可靠口径的下载量。主要操作固定在行尾，内容过长时省略且不挤压按钮。

### 4.1 图标体系（新增功能强制遵循）

图标分为两层，新增功能和页面不得混用：

1. **系统功能图标**：导航、搜索、设置、上传、编辑、删除、刷新、翻页、关闭和状态反馈统一使用本地 Lucide 线性图标，通过 `assets/v210-icon.js` 的 `<xianma-icon name="..."></xianma-icon>` 调用。正式页面必须在需要调用图标的内联脚本之前同步加载该组件，不使用 CDN。
2. **业务内容图标**：技能、提示词、技能搜索结果、技能调用和定时任务继续使用当前彩色 Emoji，例如 `📅、🖼️、✍️、📝`。同一技能或提示词跨技能库、搜索、调用、任务结果和定时任务页面必须使用同一个业务图标；业务 Emoji 不进入系统图标组件。

系统图标默认映射如下；已有语义必须复用，不得为同一动作另选图标：

| 语义 | 图标名 | 语义 | 图标名 |
| --- | --- | --- | --- |
| 新对话 | `square-pen` | 需求提报 | `clipboard-pen-line` |
| 搜索 | `search` | 提示词库 | `lightbulb` |
| 技能库 | `zap` | 定时任务 | `clock-3` |
| 设置 | `settings` | 退出 | `log-out` |
| 附件 | `paperclip` | 新增 | `plus` |
| 刷新 | `rotate-cw` | 关闭/移除 | `x` |
| 删除 | `trash` | 上传 | `upload` |
| 返回 | `arrow-left` | 进入/前进 | `arrow-right` |
| 上一页 | `chevron-left` | 下一页 | `chevron-right` |
| 展开 | `chevron-down` | 成功 | `circle-check` |
| 失败/取消 | `circle-x` | 警告 | `triangle-alert` |
| 工作台 | `home` | 业务管理 | `panels` |
| 数据中心 | `chart` | 浏览器工具 | `globe` |
| 文件 | `file` | 文件夹 | `folder` |
| AI Studio 模块 | `sparkles` |  |  |

视觉与可访问性规则：

- 普通按钮和输入辅助图标固定 16px，侧栏导航固定 18px，卡片或模块入口固定 20px；统一线宽 1.75px、`currentColor`，不得随文案或视口缩放。
- 系统图标默认使用灰色，选中态继承山茶红 `#D9353F`；状态图标继承对应成功、警告或危险色。
- 纯图标按钮固定 32×32px，必须提供 `aria-label` 和 Tooltip；带文字按钮中的装饰图标使用 `aria-hidden="true"`，不得重复朗读。
- 页面不得直接写系统 Emoji、Unicode 字符图标、手工复制的内联 SVG 或外链图标库；数据图表 SVG 不属于图标，不受此条限制。
- 新增功能开始前必须依次读取项目 `AGENTS.md`、本文件和 `assets/v210-icon.js`。先在映射表中选用已有语义；没有映射时，先说明新增语义、复用范围和与现有图标的关系，确认后同步更新本文件与公共组件，禁止在单页临时补图标。

## 5. 状态与反馈

- 用户端技能一级状态统一为 `仅自己可用 / 发布处理中 / 需修改 / 企业已发布 / 企业已下架`。后台业务状态映射为：未提交、已撤回 → 仅自己可用；审批中、待发布 → 发布处理中；已驳回 → 需修改；已发布 → 企业已发布；已下架 → 企业已下架。
- 审批中和待发布不新增用户端一级状态，使用辅助文案分别说明“等待管理员审批”和“已通过，等待发布”。
- 加载：按钮进入禁用态并显示“处理中”。
- 空状态：说明当前筛选无结果，并提供清空筛选操作。
- 错误：错误文字紧邻输入或校验结果，保留修改和重试入口。
- 禁用：降低对比度并显示不可操作原因。
- 成功：页面内状态更新 + 短暂 Toast，不只依赖 Toast。
- 下架：企业技能调用按钮禁用；创建者个人版本在“我的技能”仍可调用。

## 6. 文案

- 浏览器任务按“禁止项 → 仅网址或仅命令 → 目标明确度 → 导航/只读/执行”判断；目标页面、目标和对象未同时明确时先追问，不创建任务。
- 浏览器页面由 AI 自动决定复用当前页面、匹配页面或打开受控页面；不向用户展示选页面、开新页面、接管或交还操作。
- 浏览器运行中只显示“查看页面”和“暂停”；暂停后同一位置切换为“继续”。网页、内容和文件均可构成任务结果，只有真实文件才出现打开文件和在文件夹中显示。
- 只发送网址统一追问“你希望我在这个网站完成什么？”；打开网址只导航；总结页面只读；禁止项在创建任务前直接拒绝。
- 命令使用明确动词：导入技能、提交审批、撤回申请、发布、下架。
- 风险提示写清对象和影响范围，例如“下架后所有员工将无法调用该企业技能”。
- 原型数据使用角色或部门占位，不使用真实员工、客户、订单或经营数据。
- 正式管理后台列表及记录中的时间统一显示为 `YYYY-MM-DD HH:mm`，月、日、时、分补零；不使用“今天”“昨天”“刚刚”或“几分钟前”等相对时间。

## 7. 文件与目录命名

- 页面按使用端分为 `应用端/` 和 `管理后台/` 两个文件夹。
- HTML 统一采用中文“端_模块_页面”命名，例如 `应用端_技能库_导入.html`。
- 同一页面内的页签不拆成重复 HTML；只有独立路由或独立交互流程才建立页面文件。
- 管理后台整体架构已定稿为“首页、技能管理、用户管理、需求管理、基础配置、版本发布”。`管理后台_技能管理.html` 是技能管理正式原型；“交互草稿”后缀文件仅作只读历史参考，不纳入菜单、开发、验收或截图范围，也无需继续同步。

## 8. 管理后台信息架构

### 8.1 外壳与导航

- 管理后台不是独立系统，必须嵌入现有聚合管理后台。
- 保留宿主左侧导航和顶部账户栏；左侧只标识当前进入“先马·AI Studio”，不得在左侧重复展开模块页面。
- AI Studio 模块顶部横向导航固定为：`首页`、`技能管理`、`用户管理`、`需求管理`、`基础配置`、`版本发布`。
- 一级页面通过顶部导航互跳；页面内部存在不同业务队列时使用二级文字页签，不把同一页签拆成多个 HTML。
- 已有“版本发布”能力继续保留并统一到新版后台样式；本期不展示偏开发运维的“运行管理”，也不预留不可点击菜单占位。

### 8.2 页面结构

```text
聚合管理后台

   │  └─ 企业技能

```

## 9. 管理后台页面规范

### 9.1 首页

- 页面第一层为“实时概况”，分两组展示：平台覆盖包含累计用户、当前有效用户、当前在线、近 30 天活跃设备；技能治理包含企业技能数、待审批数、待发布数。
- 第二层展示周期指标：访问用户、活跃用户、任务用户、任务数、成功数、失败数、成功率、企业技能调用次数。
- 周期筛选默认“今日”，支持近 7 天、近 30 天和自定义日期；时间选择变化后只刷新周期指标、趋势和排行，不刷新实时累计。
- 待审批、待发布实时卡片内直接提供“去审批”“去发布”，数字与对应列表状态一致；首页不再设置独立待处理工作台。
- 趋势使用任务数、成功数、失败数三条序列；功能使用排行按“模块访问人数 + 关键操作人数/次数”展示，不使用页面点击量替代。
- 趋势粒度随范围自动变化：今日每 2 小时、近 7 天按天、近 30 天按北京时间自然周；自定义 1 天按 2 小时、2-14 天按天、15-90 天按自然周、91 天及以上按自然月。自定义天数包含起止日期，周粒度首尾不足一周分别展示。
- 趋势标题旁必须展示当前统计粒度；横轴标签随粒度显示时段、日期、周范围或月份，不得统一显示“按日期统计”。
- 任务按首次进入执行时间归桶，后续重试或状态变化只更新原时间桶的最终状态，不因完成时间迁移。
- 首页实时卡口径：累计用户为历史上至少成功进入过一次 AI Studio 的去重用户，停用、离职或取消权限后仍保留且只增不减；当前有效用户为当前仍有 AI Studio 使用资格的用户；当前在线为最近 5 分钟存在有效心跳的去重用户；近 30 天活跃设备为最近 30 天存在有效心跳的去重设备。企业技能数为已发布和已下架的企业对象数，并辅助展示其中已发布数；待审批、待发布分别按后台对应当前状态统计。
- 周期指标卡必须在指标名下展示短口径：访问用户“周期内去重”、活跃用户“完成关键操作”、任务用户“发起有效任务”、任务数“首次进入执行”、成功数“最终状态成功”、失败数“最终状态失败”、成功率“成功 /（成功 + 失败）”、企业技能调用“实际开始执行”。不得展示无统计基准的涨跌标识。
- 趋势图固定展示任务数、成功数、失败数；空桶补 0，未来桶不展示。横轴按粒度使用 `HH:mm-HH:mm / MM-DD / MM-DD~MM-DD / YYYY-MM`，悬停展示完整桶范围与三项数值；图例默认全开并支持显隐。无数据、加载和失败均在图表原区域给出明确状态。
- 功能排行首期纳入 AI 对话、技能库、浏览器工具、搜索、提示词库、定时任务、任务结果，首页展示前 5。主排序按关键操作人数降序，并列依次按关键操作次数、访问人数和固定模块顺序；每行展示访问人数/次数、关键操作人数/次数和关键操作转化率，不将访问与关键操作相加。
- 页面型模块在页面成为当前前台页面时计访问；浏览器工具在显式命令发送或自然语言识别后展示工具调用时计触达。同页刷新、组件重渲染、筛选和前后台切换不重复计。技能库排行只统计从技能库发起的使用，对话中直接调用技能不重复归入技能库。
- 首页统一展示：完整零值显示 `0`，分母为零或不适用显示 `—`，未采集且不可重算显示“历史不可补算”，百分比保留 1 位小数，计数使用整数和千分位。取数失败不得显示 0，保留旧值时必须标注“上次成功数据”。
- 任务趋势与功能排行之后展示“客户端版本分布”。基数固定为近 30 天活跃设备，每台设备取最后一次有效心跳的客户端版本；每项显示版本号、设备数、占比和最新版本标识，未知版本单列且排在最后。版本设备数总和必须等于近 30 天活跃设备，点击版本项进入“版本发布”。本期不展示设备明细、历史趋势或升级漏斗。
- 页面“数据更新时间”只有在实时卡、周期指标、趋势、排行和客户端版本分布全部成功取数后更新；任一区域失败时保留原时间，并在失败区域标注“更新失败/上次成功数据”。
- 今日为当日 00:00 至查询时刻；近 7 天含今日及前 6 个自然日；近 30 天含今日及前 29 个自然日；自定义包含起止日期且结束日不得晚于今日。周期切换、自定义应用同步刷新周期卡、趋势及排行；手动刷新同时更新实时卡与周期区域。实时卡是最近一次成功取数时的当前状态快照，不承诺秒级自动刷新。
- 访问用户按周期内有效前台访问去重，客户端启动或从后台恢复为前台且身份有效时计访问；Token 刷新和后台心跳不计。任务用户必须小于等于活跃用户，活跃用户必须小于等于访问用户。
- 一期不提供独立数据页、复杂漏斗、自定义看板、留存和经营收益分析。
- 旧版“使用统计”不继续保留独立页面，原入口进入新版首页。旧版真实用户、心跳、设备和版本明细优先复用；只有累计汇总值时仅作为切换日累计用户基线，不反向生成用户或设备明细，无法还原的历史活跃与版本分布不补算。

### 9.2 技能管理

- 二级页签为“技能审批”“待发布”“企业技能”，页签数量与当前列表同步。
- 筛选栏顺序为搜索、状态/分类筛选、重置；主要动作“直接发布企业技能”固定在页面标题区右侧。
- 分类筛选读取全部 12 个默认分类，使用可检索多选下拉；多个分类按任一匹配。技能审批、技能导入和直接发布的分类字段仍为可检索单选。
- 审批详情使用弹窗或右侧抽屉，完整展示技能名称、提交人、版本、说明、分类、标签和校验结果。
- 审批通过后进入待发布，不自动发布；驳回原因必填。
- 审批阶段可规范企业副本分类和标签，不覆盖员工个人技能元数据；管理员直接发布也必须选择分类和标签。
- 员工撤回与管理员审批并发时，第一笔成功操作生效；另一端提示状态已变化并刷新，不重复生成待发布记录。
- 待发布操作必须先校验企业名称唯一性；冲突时允许修改企业发布名称，但不得改员工个人技能名称。
- 企业技能行内保留“查看”和一个状态操作：已发布可下架，已下架可重新发布。
- 后台审批、待发布和企业技能列表保留版本号展示，首次上传或发布统一为 `v1.0`；本期不提供技能版本更新、历史版本或版本回退入口。
- 企业技能列表展示创建人和累计调用次数。员工提交后发布时创建人显示员工花名；管理员后台直接新增时显示管理员用户名，审批人和发布人不得覆盖创建人。
- 累计调用次数不受首页时间筛选影响；只有成功创建任务且该企业技能实际开始执行才增加，搜索、点击、查看详情和仅选择技能不计，同一任务内重试不重复增加。
- 下架和重新发布必须说明影响范围并二次确认；成功后同时更新列表状态并显示 Toast。重新发布沿用同一份内容和 `v1.0`，不产生新版本。
- 管理员直接导入企业技能时，导入来源支持本地文件夹、GitHub 地址和 ZIP 压缩包；校验通过后直接发布，无需审批。

### 9.3 用户管理

- 一期只有“AI Studio 用户”列表，不重复建设聚合后台账号体系。
- 列表展示姓名/账号标识、账号状态、在线状态、累计任务数、首次登录、最后登录、最近活跃。
- 用户详情展示任务数、成功数、失败数、成功率和技能调用次数，只展示统计和元数据；成功率按 `成功数 /（成功数 + 失败数）` 计算，执行中、部分成功和已取消不进入分母。
- 列表与详情均为截至数据更新时间的累计口径，不跟随首页周期筛选。累计任务按首次进入执行的 `taskId` 去重；技能调用同时包含个人与企业技能实际开始执行的主调用，按 `taskId + skillId` 去重。
- 首次登录为第一次成功进入 AI Studio，同时作为“注册时间”；最后登录只在新登录会话建立时更新，Token 刷新和心跳不更新；最近活跃为最后一次已定义关键操作时间，从未关键操作显示 `—`。
- 在线表示客户端连接且最近 5 分钟有有效心跳；超时或账号停用显示离线。停用不清空历史累计、首次登录和最近活跃。
- 不提供新增/删除账号、重置密码，不展示员工对话、提示词、网页或文件正文。

### 9.4 基础配置

- 二级页签为“分类管理”和“标签管理”，两个页签均使用独立列表，不采用左右并排双面板。
- 分类支持新增、编辑、启用、停用；名称不可重复。已被技能引用的分类不能删除，必须先迁移引用。
- 标签支持搜索、新增、编辑、合并、停用和删除；有引用时删除入口禁用并提示需先合并、迁移或停用，无引用时二次确认后删除。
- 删除不是默认操作：有引用时只允许停用或迁移，无引用时仍需二次确认。

### 9.5 版本发布

- 版本发布是已有能力，迁移至新版管理后台时保留原业务字段和流程，不改为开发运维菜单。
- 发布表单保留显示版本、系统建议的内部更新版本、更新渠道、更新标题、更新内容、Windows 安装包和强制更新。
- 内部更新版本由系统自动建议，管理员不可手工修改；显示版本、更新标题、更新内容和安装包为必填项。
- 更新内容支持逐行填写，员工端按版本说明展示；不得把内部测试信息、凭据或敏感地址写入版本说明。
- 安装包上传应展示文件名、大小和上传进度；上传失败保留表单内容并提供重试。
- “上传并发布”仅在后台连接正常、必填项完整且安装包上传完成后可用；提交中禁止重复操作。
- 强制更新默认关闭；勾选后发布确认必须明确“员工不能选择稍后提醒”的影响。
- 已发布版本按发布时间倒序展示显示版本、内部版本、渠道、更新标题、强制更新状态、发布时间和发布状态。
- 撤回版本需要二次确认；撤回后尚未更新的客户端不再看到该版本，已完成更新的客户端不会自动降级。

## 10. 后台公共组件

- 页面标题区：左侧标题与一句业务说明，右侧最多放一个主按钮和一个次按钮。
- 数据卡片：同组等高，标签 12px、数值 24px、口径说明 12px；待审批和待发布卡片可在说明行右侧放一个文字入口，其他卡片不承担跳转时不显示悬停效果。
- 筛选栏：输入和选择控件高度统一为 40px；1024px 下允许换行，但主操作不得被挤出可视区。
- 表格：表头固定浅灰底，状态必须“文字 + 颜色”；操作列右侧固定宽度并保持单行，表格不足宽度时横向滚动。
- 分页：位于表格下方，左侧显示结果范围，右侧显示页码和每页条数。
- 二级页签：使用文字和 2px 山茶红下划线；数字使用普通辅助文本，不使用胶囊形导航。
- 详情抽屉：宽 520-640px，适合连续查看列表对象；弹窗宽 480-640px，适合确认和短表单。
- 审计时间线：按时间倒序展示操作者、动作、结果和原因，不展示敏感正文。
- 危险操作：确认按钮使用危险色；确认文案必须包含对象、影响用户和是否可恢复。

## 11. 后台状态与响应规则

- 加载态：保留页面骨架尺寸，按钮显示“处理中”且禁止重复提交。
- 空态：位于表格内部，说明是无数据还是筛选无结果；筛选无结果时提供“清空筛选”。
- 错误态：在原区域显示失败原因与“重新加载”，不得用空白页代替。
- 禁用态：控件旁必须说明不可操作原因，例如“该分类仍被 6 个技能引用”。
- 1280px：宿主左栏 226px，模块内容保持 4 列实时指标和信息区双栏布局。
- 1024px：宿主左栏缩至 188-198px；指标自动变为 2 列；趋势与排行改为单列；表格横向滚动，操作列不折行。
- 低于 1024px 仅保证可查看，不新增移动端专属流程。
- 静态原型通过 URL 参数演示异常状态：`?demo=loading`、`?demo=empty`、`?demo=error`；参数仅用于本地评审，不在正式页面增加可见的调试控件。
- 后台首页的 `empty` 只替换图表与排行数据区，保留指标口径；`error` 保留上次成功数据并明确提示数据时间和重新加载入口。

## 12. V2.1.0 需求提报增量规范

### 12.1 应用端入口与对话

- 应用端左侧导航固定按“新对话、搜索、技能库、提示词库、定时任务、需求提报”排列；“需求提报”位于末尾并与日常任务入口视觉分组。“我的提报”不作为一级导航，属于需求提报模块子页面，只从需求提报页内进入。
- 需求提报和我的提报页面的公共侧栏继续展示原有项目及普通 AI 对话记录，不展示需求提报对话历史；点击普通对话离开时自动保存当前需求草稿，再次点击“需求提报”恢复该草稿。
- 本期最多保留一条未提交需求草稿：没有草稿时点击“需求提报”进入空白新需求对话；存在草稿时自动恢复上次位置，不提供多草稿列表、草稿搜索、归档或切换。
- 页面不展示供用户手动切换分析阶段的状态下拉框；分析中、待确认、待提交和已提交均由对话流程自动推进。
- 一条需求提报对话只分析一条 AI Studio 自身需求；明显独立的第二条需求需另行发起。
- 正式产品由 Agent 在第一个实质性问题前读取随当前版本部署的 `docs/AI_CAPABILITIES.md`，并展示能力资料读取成功、异常或过期状态；当前静态原型不包含该文件，也不执行真实读取，仅用预设演示数据表达对应状态。
- 能力关系统一为：现有能力直接解决、现有能力部分解决、当前无对应能力、暂时无法判断。
- 现有能力可直接解决时，先展示对应能力和使用建议；提报人确认问题已解决后结束本次分析且不生成需求记录，确认仍有未覆盖差距时再进入逐轮追问。
- 对话每轮只问一个最高价值问题；每两至三轮有效回答后展示阶段总结并允许用户纠正。
- 分析完整后同时展示需求摘要、现有能力对比、建议解决方向和 AI 提交建议。
- “确认摘要”和“确认提交”必须是两个独立动作；摘要确认后明确提示“目前尚未提交”。
- 已知提交接口不可用时保持待提交状态，不得显示已提交；接口返回成功和唯一需求 ID 后才能显示已提交。
- 建议补充状态不能普通提交；暂不建议提交时允许提报人填写理由坚持提交，也允许选择“暂不提交”。选择暂不提交后状态改为“已暂存”，保留为唯一草稿，可稍后继续补充并重新生成摘要和提交建议。
- 未提交需求在切换到搜索、技能或普通对话后仍保持唯一草稿；再次进入“需求提报”时自动恢复原始描述、问答记录、当前问题、分析阶段、完整度、能力关系、已确认事实和建议方案，并可从上次位置继续回答，不得回到空白初始页。
- V2.1.0 静态原型使用浏览器本地存储演示恢复；生产端必须按 `conversation_id` 持久化结构化草稿，不依赖重放完整聊天，也不能依赖单台电脑的 localStorage。
- 恢复时重新读取当前能力资料；若能力关系、差距、建议、范围或摘要发生实质变化，原摘要确认与提交授权失效并退回待确认。
- 存在草稿时发起新需求，必须提示“继续当前需求 / 放弃并新建”；放弃属于破坏性操作，二次确认后清除当前草稿且不可恢复。本期不保留已放弃、现有能力已解决或范围外需求的历史记录。
- 正式提交成功后清除未完成草稿恢复入口，已提交内容从“我的提报”只读查看。
- 静态原型不调用真实模型、Agent 或 Skill，只模拟能力核对、追问、总结和提交分支；正式产品由 Agent 层调用需求分析 Skill，页面只负责对话与结构化状态展示，不直接读取或执行本地 `SKILL.md`。
- 需求分析、能力对比、建议方向、MVP范围、风险、验证方式和是否建议提交统一展示 Skill 输出；技术层只校验结构、枚举、状态、权限、版本、跨字段一致性与幂等，不得在页面或编排层另做业务判断。
- 静态原型通过 URL 参数验证分支：`?scenario=direct`、`?scenario=supplement`、`?scenario=not-recommended`、`?scenario=capability-error`、`?scenario=out-of-scope`、`?scenario=submit-error`；参数只用于本地评审，不增加员工可见的调试控件。
- 为方便现场演示，静态原型在空白需求页首条消息完全匹配 `测试不提交`、`测试提交`、`测试坚持提交` 时，分别预设“暂不建议后暂存”“建议提交”“暂不建议后坚持提交”的判断分支；三个口令仍完整经过四轮追问、阶段总结、摘要确认和对应提交动作，不直接跳转结果。口令只属于原型测试数据，不进入正式产品的意图识别、AI判断或生产规则。

### 12.2 我的提报

- “我的提报”是需求提报模块子页面，只从需求提报页右侧“查看我的提报”或提交完成后的入口进入，不在应用左侧设置独立一级入口。
- 子页面继续保持“需求提报”为左侧选中项，并提供“提报新需求”返回需求对话。
- 列表展示标题、提交时间、能力关系、AI建议和“已提交”状态。
- 列表需要同时演示正常提交与提报人坚持提交；坚持提交必须保留“暂不建议提交”的 AI 原始判断、坚持提交标记和理由，不得改写为建议提交。
- 详情展示提交时保存的结构化需求、能力对比、建议解决方向、AI判断与确认记录。
- 已提交详情只读；需要修改时重新发起一条需求。
- 员工端只展示“已提交”，不展示后台“未导出/已导出”状态，避免将导出误解为立项、排期或开发承诺。

### 12.3 后台需求管理

- AI Studio 模块顶部导航在“用户管理”和“基础配置”之间设置一级菜单“需求管理”，保持核心治理顺序为技能、用户、需求，再进入配置与发布。
- 后台第一期只负责查看、搜索、筛选、查看详情和导出 Markdown，不做审核、通过、驳回、退回、负责人、优先级、排期、评论或开发状态流转。
- 列表默认按提交时间倒序；列顺序固定为“需求 ID、需求标题、提报人/部门、AI建议/提交方式、提交时间、导出状态、操作”，需求 ID 与标题不得混在同一字段。MVP 只保留需求 ID/标题/真实问题/提报人搜索和导出状态筛选，完整需求 ID 必须可精确命中。AI 建议与能力关系在列表和详情中展示，但不提供独立筛选控件。
- 列表必须区分正常提交与坚持提交；坚持提交不得改写为 AI建议提交。
- 详情使用独立页面，完整展示：原始诉求、需求分析、能力资料版本与匹配、建议解决方向、范围风险、AI判断、用户确认和导出记录。
- 后台不得修改需求正文、AI原始判断或用户确认结果。

### 12.4 导出与编号

- 提交成功时由提交服务生成唯一需求 ID，格式为 `REQ-YYYYMMDD-NNN`；日期按北京时间提交日期，序号由服务端并发安全机制保证当日唯一。
- 用户端“我的提报”和管理后台均展示同一需求 ID；Skill、前端和导出服务不得生成或替换编号。
- 管理后台首次及重复导出 Markdown 均沿用提交时的需求 ID；记录首次导出时间、最近导出时间和导出次数，导出状态不得影响提交状态。
- 导出内容包括需求分析、能力对比、建议解决方向、范围风险、AI判断、提报人确认和坚持提交理由（如有）。
- V2.1.0 只支持单条导出，不提供批量选择、批量导出、合并 Markdown 或 ZIP 打包。

### 12.5 展示边界

- 建议解决方向必须标记为 AI 建议，不等于正式 PRD、交互原型、技术方案、立项、排期或开发授权。
- 能力资料异常时不得显示确定的“已有功能可解决”或“当前无对应能力”，方案只能标记为条件性建议。
- 后台和应用端不展示完整聊天全文，只保存必要原始诉求摘录和结构化结果。
- 原型示例仅用于验证信息层级和交互，不代表测试能力资料、统计数字、部门角色或需求已经存在于生产环境。

## 13. V2.1.0 本地文件自动化 MVP 增量规范

### 13.1 入口与支持范围

- 本地文件能力不新增侧栏一级入口，统一从“新对话”通过自然语言识别、`/本地文件` 工具或首页建议项进入同一任务流程；工具标识为 `skill=local-file`。
- “技能与工具”中的名称为“本地文件”，说明为“查找、整理并处理授权工作区中的 Excel、Word、PPT”，系统图标复用 `<xianma-icon name="file">`。
- 支持 `.xlsx`、`.csv`、`.docx`、`.pptx`；旧版 `.xls`、`.doc`、`.ppt`、含宏文件和加密文件本期不支持。附件或命令没有具体任务描述时只追问，不创建任务。
- 静态原型不读取真实 Office 文件、不调用真实模型、不控制 WPS、Office 或其他本机软件，文件名、字段和统计均为脱敏演示数据。

### 13.2 Excel 完整流程

- 主演示任务为“将新品源表转填至固定登记模板”：选择固定源表与固定登记模板，校验格式、工作表和必要字段，展示执行计划与输出位置，用户确认后再模拟字段映射、生成和逐项校验。
- 默认输出 `新品登记表_处理后.xlsx`，不修改源表和原模板；同名时默认保存为副本，选择覆盖需再次确认。
- 缺失、重复和格式错误进入异常清单，不静默补值；结果必须区分正常项、异常项和未处理项，并提供“打开文件”“在文件夹中显示”“查看执行详情”。

### 13.3 Word 与 PPT 简化流程

- Word：选择 `.docx`，展示需发送模型的段落范围和用途，获得单次授权后生成结构化整理版 Word，并展示提取摘要和新文件。
- PPT：选择提纲或 Word 与固定模板，展示需发送模型的段落范围和用途，获得单次授权后生成 PPT，并展示页数、页面提纲和新文件。
- 两条简版流程只覆盖选择文件、内容授权、处理中、成功和失败，不展开复杂编辑或 Office 软件控制分支。

### 13.4 权限、异常与记录

- 首次访问工作区时展示授权目录和本次文件范围；越界文件必须重新选择，拒绝授权或依赖模型而未获内容授权时保持未执行，不生成结果，也不得显示已上传。
- 模型内容授权必须展示文件名、Sheet/段落、字段范围和用途，仅提供“允许本次”，不得默认勾选或跨任务复用。
- 覆盖文件、批量移动等不可逆操作单独确认；加密、占用、损坏、必要字段缺失、部分成功和失败均提供明确结果态和下一步。
- 执行详情只记录任务编号、路径元数据、动作、授权决定、结果和错误，不展示或保存文件正文。浏览器本地状态以 `xianmaLocalFileTaskState:{taskId}` 隔离，仅保存演示阶段、文件元数据、授权、结果和事件。
- 原型演示场景为 `file-excel`、`file-word`、`file-ppt`、`file-partial`、`file-permission-denied`、`file-error`；口令为 `测试Excel`、`测试Word`、`测试PPT`，参数和口令只服务本地评审。

### 13.5 响应与布局

- 本地文件任务复用现有任务状态条、步骤日志、确认弹窗、结果卡、执行详情抽屉和公共输入框，不创建独立文件工作台页面或新公共组件。

## 14. V2.1.0 定时任务 MVP 增量规范

### 14.1 入口与统一创建契约

- 原一级入口“已安排”统一改名为“定时任务”；历史文件 `应用端_已安排.html` 保留文件名，避免破坏既有链接。
- 定时任务支持两个入口：定时任务页右上角“新增定时任务”，以及普通对话中的自然语言识别或 `/定时任务` 显式调用。两种入口必须生成同一结构的任务草稿，并在用户确认后才创建。
- 普通对话只有时间、没有明确任务内容时只追问，不创建空任务；创建后冻结任务指令、周期和工作区，后续普通消息不得隐式修改。
- 系统入口与操作图标继续复用 `<xianma-icon>`：导航使用 `clock-3`，新增使用 `plus`，记录使用 `file`，删除使用 `trash`，关闭使用 `x`，状态使用 `circle-check`、`triangle-alert` 或 `circle-x`。业务任务图标继续使用对应彩色 Emoji。

### 14.2 周期、状态与执行

- MVP 只支持单次、每天、每周；不支持每月、自定义 Cron、事件触发、多任务依赖和自动重试。
- `立即运行` 或 `补跑`只增加一次独立运行，不改变原定计划；单次任务成功后进入“已完成”，周期任务继续保留下一次计划。
- 状态至少覆盖运行中、已暂停、已错过、待确认、执行成功和执行失败。启停开关仅控制后续计划，不删除历史运行记录。
- 客户端在线或后台常驻时才按计划执行；客户端关闭期间到期的任务记为“已错过”，重新打开后允许人工补跑，不得展示为已自动完成。
- 每次执行形成独立记录，结果摘要回写创建任务的对话，并同步进入定时任务运行记录；记录可进入现有任务结果页，不新建结果页面。

### 14.3 权限与 MVP 边界

- 定时任务可绑定一个授权工作区，访问范围外的文件必须重新选择；高风险或缺少授权的动作在运行时进入“待确认”，不得静默执行。
- 本地文件正文需要发送模型时仍遵循单次内容授权，定时任务不得把一次授权扩大为永久授权；未取得当次授权时保持待确认且不生成结果。
- 本期不建设客户端关闭后的云端执行、企业共享模板、多设备同步或技能组合编排；技能组合继续作为后续版本能力。

### 14.4 页面与响应规则

- 定时任务页复用公共应用外壳和侧栏。页面头部保留标题、状态说明及唯一主操作“新增定时任务”；任务列表采用紧凑行卡，展示任务名称、指令摘要、周期、下次运行、最近结果、状态和操作。
- 创建/编辑使用同一弹窗；运行记录使用侧边抽屉；删除使用二次确认弹窗。弹窗内容区可滚动，标题与底部操作固定可见。
- 1024px 与 1280px 下任务名称、周期、状态和主要操作不得遮挡；较窄视口允许操作换行，不允许整页横向滚动或公共侧栏跳动。
- 1024px 与 1280px 下保持公共侧栏、对话列和底部输入框位置稳定；结果信息网格在窄窗口改为单列，按钮允许换行但不得遮挡正文。

# 先马·AI Studio V2.1.0 技能库需求说明

> 更新时间：2026-08-13  
> 状态：规则已确认，原型已同步，可交开发技术评审与任务拆分  
> 范围：2026 年 8 月技能库优化；不代表功能已开发、已验收或已上线

## 1. 目标

让员工导入的个人技能立即可用，并通过“提交、审批、发布、搜索调用、下架”形成可治理的企业技能闭环。管理端嵌入现有聚合管理后台，不建设独立后台框架。

## 2. 角色与入口

| 角色 | 入口 | 本期能力 |
| --- | --- | --- |
| 员工 | 桌面应用“技能” | 查看全部/我的/企业技能，导入、调用、提交、撤回、修改、重新提交 |
| 管理员 | 聚合管理后台“先马·AI Studio” | 一级审批、驳回、发布、下架、分类与标签管理、直接上传并发布 |

## 3. 员工端规则

1. 技能页包含“全部技能、我的技能、企业技能”。
2. 支持导入本地 Skill 文件夹、公开 GitHub 仓库地址和 ZIP 压缩包。
3. 导入时校验 `SKILL.md`；校验成功后进入“我的技能”并立即可用。
   - 产品最低校验为：来源可读取、根目录可识别 `SKILL.md`、必要元数据与说明可解析、兼容当前客户端及授权工具、不含明文敏感凭据、越权包外路径或明确禁止能力。
   - 校验失败不得创建、安装或发布技能，必须返回可定位的失败类型和处理建议；ZIP 安全、阈值、脚本/二进制和依赖扫描方式由开发与安全设计，不在原型中展开。
4. 后台保留未提交、审批中、已撤回、已驳回、待发布、已发布、已下架等业务状态；用户端一级状态只显示“仅自己可用、发布处理中、需修改、企业已发布、企业已下架”。其中未提交/已撤回映射为“仅自己可用”，审批中/待发布映射为“发布处理中”，已驳回映射为“需修改”。
5. 未提交、已撤回和已驳回的个人技能可编辑、调用、提交或删除；删除后本人不能再调用，且不可恢复。
6. 审批中的个人技能可继续调用，也可撤回；如需删除必须先撤回，避免与管理员审批并发。
7. 已驳回技能不影响个人调用，可修改后重新提交。
8. 已发布企业技能下架后，全体员工不能再调用企业副本；创建者的个人版本仍保留并可用。
9. 待发布、已发布和已下架状态下，员工仍可删除自己的个人技能；删除只影响个人副本，不影响已形成的企业副本。企业技能保存独立发布快照，不依赖员工个人技能继续运行。
10. “我的技能”无论是否提交审批，均提供“使用”入口；“管理”入口单独用于查看状态、编辑和提交审批。
11. 点击“使用”后新建一条独立对话，自动带入 `/技能名称`；员工可上传文件或补充任务描述，发送后调用该技能。
12. 未提交和已驳回技能可编辑名称、简介、分类、标签和技能说明；审批中需先撤回。待发布、已发布和已下架技能本期不支持更新内容。
13. 技能库提供“在线技能库”入口，员工可搜索公开技能，或粘贴公开 GitHub 技能仓库地址查找技能。
14. 在线技能库只从 GitHub 公开仓库获取技能，默认过滤与当前客户端不兼容的技能；列表展示技能名称、简介、GitHub 仓库所有者、仓库来源、兼容状态和安装状态，不展示无可靠口径的下载量。
15. 在线技能安装前执行兼容性与 `SKILL.md` 校验；安装成功后进入“我的技能”，状态为“未提交”并立即可用。当前 V2.1.0 原型使用模拟数据，不代表 GitHub 搜索与安装能力已经接入。
16. 同一员工的“我的技能”内名称必须唯一；不同员工的个人技能允许重名。导入、在线安装、编辑和管理员发布等全部入口统一按去除名称首尾空格、英文字母不区分大小写的规则校验。
17. 个人技能与企业技能允许同名；斜杠菜单同名时显示“个人”或“企业”来源，调用以稳定技能 ID 为准，不按名称猜测。
18. 企业技能执行中被下架或员工权限被回收时，任务立即暂停并停止新的读取、生成和外部变更；已完成结果保留。权限恢复后可继续，否则由员工结束任务并记录真实终态。

## 4. 管理端规则

1. 管理端嵌入现有聚合管理后台。宿主左侧导航保持不变，先马·AI Studio 模块内部使用顶部横向导航。
2. 管理后台架构已定稿，顶部导航包含：首页、技能管理、用户管理、需求管理、基础配置、版本发布。
3. 有后台权限的管理员执行一级审批，可以审批自己提交的技能。
4. 审批通过后进入“待发布”，由管理员手动发布；发布后可下架。
5. 管理员可从后台直接导入企业技能，校验通过后无需审批，直接发布。
6. 管理员只能管理企业副本，不能删除员工个人技能。
7. 本期企业技能不提供彻底删除入口；违规或高风险内容先下架并保留审计，后续处置另行迭代。
8. 本期不做技能版本更新、历史版本和版本回退。后台保留版本号字段，首次上传或发布统一显示 `v1.0`，仅为后续版本能力预留。
9. 本期企业技能默认全员可见，不提供部门权限配置界面；数据结构预留部门、岗位、人员权限扩展。
10. GitHub 一期只支持公开仓库和一次性复制，不自动同步。
11. 企业技能库内名称全局唯一，重名判断去除名称首尾空格，英文字母不区分大小写。不同员工提交同名技能时允许进入审批；管理员必须在发布前确定不重复的企业名称，名称冲突时禁止发布且不修改员工个人技能名称。
12. 管理员直接发布企业技能时必须填写分类和标签；审批阶段可规范企业副本的分类和标签，但不得改写员工个人技能元数据。
13. 员工撤回与管理员审批并发时，以服务端最先成功的状态变更为准；后提交的一方提示“状态已变化，请刷新”，不得重复生成待发布记录。

> 管理后台整体信息架构和一级菜单已定稿。技能审批与企业技能治理统一归入“技能管理”，分类与标签归入“基础配置”，首页承载核心数据和待审批/待发布跳转入口。

## 5. 分类与标签

- 分类由管理后台统一维护，应用端只允许选择，不允许新增或申请新增。
- 默认分类为：办公协同、开发工具、投资理财、效率工具、内容创作、信息资讯、教育学习、数据分析、网站部署、生活服务、商业运营、知识与学习。
- 分类选择使用可检索单选下拉，显示当前选中项，不允许从应用端新增。
- 管理端技能列表的分类筛选支持从 12 个默认分类中检索、多选，多个分类按任一匹配筛选；技能导入、审批规范和直接发布仍为分类单选。
- 标签支持输入检索、多选；没有匹配项时可直接新增。技能进入企业库前由管理员规范标签。
- 已被技能引用的标签不可删除，只能先合并、迁移或停用；无引用标签可在二次确认后删除。已被引用的分类必须先迁移引用关系。

## 6. 审计范围

提交、撤回、审批、驳回、发布、下架和重新发布均保留操作人、时间、对象、原因与结果；违规或高风险内容的下架原因必须记录。

## 7. 在线技能库来源

- 在线技能库只从 GitHub 公开仓库获取和搜索技能，不接入第三方技能市场。
- 展示字段来自 GitHub 可核验信息与平台兼容性校验，至少包括技能名称、简介、GitHub 仓库所有者、仓库地址、兼容状态和安装状态。
- 不展示无法从 GitHub 或平台安装记录可靠取得的“下载量”；平台自己的安装量如后续需要，另行定义统计口径。
- 安装为公开仓库当前内容的一次性复制，不自动同步后续 GitHub 更新。

## 8. 原型验收口径

- 员工端可走通导入、校验、立即使用、提交、撤回、驳回后重提和状态查看。
- 个人技能卡片同时提供“使用”和“管理”；使用后进入带 `/技能名称` 的新对话，可上传文件或输入描述后发送。
- 导入和编辑均可选择后台分类，并可检索、多选或新增标签。
- 导入和编辑的分类控件均支持输入检索、单选且不可新增；标签控件保持多选并允许新增。
- 技能相关页面的应用导航图标与其他应用页面一致；选中技能时只改变背景、文字粗细和图标颜色，不替换图标。
- 在线技能库从 GitHub 公开仓库搜索或识别公开 GitHub 地址，可见仓库所有者、来源、兼容性过滤结果，并可完成“安装中—已安装—进入我的技能”的原型闭环。
- 同一员工不能创建同名个人技能；不同员工可保留同名个人技能；企业名称冲突时审批可继续但发布被阻止，管理员改为唯一企业名称后可发布。
- 未提交和已驳回场景可实际编辑并保存技能内容；待发布、已发布和已下架不提供编辑或版本更新入口。
- 企业技能可搜索调用；下架状态不可调用，创建者仍可调用个人版本。
- 后台采用宿主左侧导航 + 模块顶部导航结构。
- 管理员可审批、驳回、发布、下架和重新发布同一份已下架内容，可从后台直接导入并发布；后台只展示 `v1.0`，不提供版本更新、历史版本或回退入口。
- 分类、标签及关键空状态、错误状态、禁用状态可见且无界面重叠。

## 9. 原型目录与命名

- `../prototype/应用端/`：员工桌面应用页面，文件名采用“应用端_模块_页面”。
- `../prototype/管理后台/`：嵌入聚合管理后台的管理页面，正式菜单固定为“首页、技能管理、用户管理、需求管理、基础配置、版本发布”。技能管理开发以 `管理后台_技能管理.html` 为正式依据；`管理后台_技能库_交互草稿.html` 仅为只读历史参考，不纳入菜单、开发、验收或截图范围，也无需继续同步。
- 全部技能、我的技能和企业技能是同一技能库页面内的页签，不拆成重复 HTML。
- 公共样式与图标保留在原型根目录，由两个端共同引用。
